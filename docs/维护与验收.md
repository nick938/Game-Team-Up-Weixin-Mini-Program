# 维护、部署与真机验收

本文保留当前运行所需的维护步骤；功能口径见 [产品说明](产品需求.md)。已完成的设计方案、分批实施记录和过期测试快照已归并，不作为当前发布通过的证据。

## 维护位置

| 内容         | 维护源与要求                                                                                                   |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| 页面和入口   | `apps/miniapp/pages.config.ts` 与页面/组件实际导航；删除页面前核对TabBar、角色入口、动态跳转、分享和搜一搜落地 |
| 应用配置     | `apps/miniapp/manifest.config.ts`；构建前由 `scripts/uni.mjs` 生成 manifest                                    |
| 版本         | `apps/miniapp/package.json`、`src/utils/changelog.ts`、根 `CHANGELOG.md`；发布时同步                           |
| 更新公告     | `apps/miniapp/src/utils/updates.ts`；新公告置顶并使用新稳定ID，不覆写已发布ID                                  |
| 群组和时间段 | `cloudfunctions/team/lib/profile-options.json`；稳定value不变，改名只改label，新选项需部署云函数并更新前端     |
| 用户权限     | `ADMIN_OPENIDS` / `admins`、`ORGANIZER_OPENIDS` / `organizers`；服务端校验角色与封禁状态                       |
| 头像         | 持久化 `cloud://` fileID，云函数转换临时HTTPS展示地址；更换失败不得保存为成功                                  |
| 反馈邮件     | `cloudfunctions/team/mail.example.js`、本地 `mail.local.js` 或服务端环境变量；密钥不提交                       |
| 主题         | `apps/miniapp/src/design` 和 `uno.config.ts`；修改构建共用主题后重启开发服务                                   |
| 车辆分享     | 页面SFC注册事件、`utils/team-share.ts` 统一文案路径、`utils/team-cover.ts` 保留车辆信息图样式                  |

群组不限制跨群上车。旧队伍保持发布时实际车头的群组快照；不要通过改用户资料批量重写历史车。没有新增字段的旧账号无需强制迁移，字段清空/保留语义由服务端兼容处理。

## 固定车与群组需求

- 固定车入口：我的 → 管理端 → 固定车。先让车头进入小程序填写昵称，按昵称或OpenID搜索选中，核对头像、昵称、群组、Steam好友码、微信ID，再设置游戏、北京时间每日时段、人数及语音。时间通过滚轮选择，人数通过加减控件调整（包含车头），保存前核对发车安排预览。新计划默认启用；暂停计划的编辑保存仍保留暂停状态，需要另点「启用」。
- `fixed_team_plans` 保存每日计划，只允许服务端管理。需先部署整个 `team` 云函数（包含 `lib/fixed-teams.js`），确认集合存在且客户端无直接写权限，保留 `startRemind` 每分钟触发器，再发布前端。保存成功后如果生成失败，界面单独说明，不重复创建计划；日志中的 `fixed car generation failed` 包含计划ID与原因。
- 开始/结束同日时直接输入HH:mm；跨午夜结束输入较早的时间。每天零点后生成当天车；有跨午夜且未结束的昨天车时支持补偿。新计划不追溯已开始的场次，不补过期车。修改、暂停不重写既有报名；需要取消当天车辆请到「组队」强制关闭。
- 群组申请经「我的 → 添加群组标识」联系作者。作者在 `cloudfunctions/team/lib/profile-options.json` 添加唯一稳定value及展示label，部署云函数并更新前端；让用户在个人资料选中群组。发车/固定车生成后会带上车头群组，旧车辆保持原快照。
- 作者微信当前沿用帮助页的 `Louisville_k`；「我的」两种申请入口均先显示用途说明，用户确认后复制，不自动发消息。
- 验收：普通用户无计划接口权限；保存/重复定时/大厅补偿每天只生成一车及一个车头；车头群组、人数、跨天日期正确；封禁车头停止发车；暂停/启用、修改次日生效、散车不复活。真机分别检查两种联系入口的说明、取消和复制；管理端核对表单标签、开始/结束时间滚轮、人数加减、车头头像与公开资料、跨天时段预览。车头资料依赖新版 `adminUsers` 返回字段，本次需重新部署 `team` 云函数再更新小程序。

## 分享注册检查

在页面 `.vue` 的 setup 中直接调用 `onShareAppMessage(page.shareAppMessage)` 和 `onShareTimeline(page.shareTimeline)`。composable 仅返回处理函数，不负责这两个原生事件的注册。

uni-app 依赖页面源码生成原生运行时标记；单测调用函数通过，也可能遗漏原生事件。微信、QQ 构建结束后自动运行 `apps/miniapp/scripts/check-share-hooks.mjs`，当前检查8个分享页面。新增分享页需同时加入检查清单。

车辆按钮使用原生 `open-type="share"` 和公开车辆标识，画布位于页面层，不包在自定义组件插槽内。分享 `promise` 的结果仍携带同一车辆的标题和详情路径，不能因刷新或切换车而串图。房间号、密码和内部身份不进入封面或原生按钮数据。

## 检查与构建

在仓库根执行 `pnpm check`，再按需执行 `pnpm build:weixin`、`pnpm build:qq`、`pnpm build:h5`；完整矩阵使用 `pnpm check:matrix`。文件监听受限时加 `CHOKIDAR_USEPOLLING=1`。

测试数量以当次输出为准，不从历史文档推断。检查源码、模拟API浏览器交互、原生构建标记、真机宿主行为和生产持久化分别确认。

独立 HTTP 传输探测仍由命令行使用，见 [p0Health](../cloudfunctions/p0Health/README.md)；探测成功不代表 QQ 登录或组队后端可用。

## 部署顺序

1. 后端有变更时部署整个 `cloudfunctions/team`（含 `lib`），选择云端安装依赖，保留 `config.json` 中的 `startRemind` 触发器及内容安全权限。
   本次移除发车联系方式输入同时取消后端联系方式必填；必须先部署云函数，再更新前端，否则新前端会被旧云函数拒绝。
2. 核对当前使用的 `users`、`teams`、`members`、`team_reactions`、`team_events`、`daily_play`、`play_options`、`fixed_team_plans`、反馈/举报及权限集合；客户端只通过云函数按权限访问。集合自动创建或索引失败按云端实际错误处理，不用截断读取伪装全量结果；保留兼容旧集合，不在文档整理时删库。
3. 构建微信，开发工具打开仓库根目录，确认产物来自 `apps/miniapp/dist/build/mp-weixin/`，再上传并设为体验版。只改前端分享不需要部署云函数。
4. 使用真实账号和体验版验收，再按微信后台流程提交审核/发布。自动上传只产生开发版本，不自动设体验版、提审、上线或部署云函数。
5. QQ HTTPS 后端独立适配登录、RPC、头像及权限；QQ 编译通过不代表已可与微信共享用户、队伍或通知。

自动上传的凭据、出口IP、Tag一致性和失败核对见 [微信 Tag 自动上传](微信Tag自动上传.md)。

## 真机验收

- “我的”白屏排查：记录用户机型、微信/QQ版本、小程序版本和报错时间，在宿主后台核对异常堆栈。资料展示与编辑会容错旧记录中非字符串的签名/联系方式，以及为 `null`、对象或含非字符串元素的群组/偏好字段，只清理展示副本，不自动改写云端记录。发布前用异常旧资料账号验证冷启动、切换“我的”、打开编辑与保存；另测无资料新账号和网络失败后的重试。自动化回归和构建通过不代替受影响用户的真机复测。
- 两个账号：首次/返回用户、完善与清空资料、互看完整公开资料、复制联系方式、更换头像及上传失败。
- 发车、编辑、再发一局与接手：确认不显示联系车头/密码/备注输入，空联系方式可提交；含旧内容的草稿/历史车/编辑记录提交后这些字段与区服/要求均为空；重复提交、并发争最后位置、满员恢复、散车、时间边界、日程重叠取消/继续和密码权限。
- 大厅默认满员可见；搜索/群组/时间筛选、重置、排序和翻页一致，不重复或丢车。
- 从大厅与详情各分享两辆不同车辆：标题、人数、时间、封面和跳转匹配，Steam不展示；右上角菜单及朋友圈分享保留相应页面内容。确认体验版自定义封面，不能只看H5或函数单测。
- 投票跨日、16:00定榜、无票/无历史、接手取消、两人并发接手与23:00后不补车；投票用户自主发车不影响官方车。
- 用户榜旧身份兼容、重复上车不增计、封禁排除；管理员与普通用户分别检查权限。
- 订阅授权、定时执行、云端发送日志和实际送达分别核对。云端写成功后的客户端失败，不应被误报为服务端保存失败。
