# 首页投票、每日待发车与用户排行

2026-10-21 按最新规则实现。首页保留「今天玩啥」，另一个入口改为「用户排行」。

## 今天玩啥

- 可以发起多个游戏投票、支持多个游戏；每人每游戏一票，同名游戏合并，不区分平台。全天可新增、投票与取消，展示紧凑的冠亚季军区域；不足三款时缺位提示「等你来发起」，并列按发起时间优先。
- 16:00保存当时的官方选车结果并生成每日待发车，开局时间固定21:00–23:00；后续票数变化不会更换这辆车。
- 有有效投票时选最高票游戏，人数沿用同游戏、同平台最近一次已完成发车的容量。没有历史设置时默认4人。
- 无人投票时，从已完成发车、未散车、游戏/平台/容量有效的历史队伍中等概率随机选择一辆，沿用游戏、平台、容量。不同历史车可重复出现同一游戏。
- 无投票也无有效历史时不虚构队伍，明确提示暂无可推荐内容。
- 系统生成的车没有车头、没有成员，房间信息为空，显示「待首位玩家发车」。投票者和提议者都不会自动上车。

官方车在大厅及详情标明「官方 · 冠军车」或「官方 · 随机车」。两个首页入口已压低高度，用户排行背景更换为奖杯与领奖台。

## 用户自己发车

每个投票选项都有「发一车」：进入普通发车页，只预填游戏信息，时间、人数由用户自行安排，并填写联系方式。每条投票卡都直接展示「我想玩」和「发一车」两个操作。不会沿用官方固定日程、容量或旧的游戏设置，也不会标成官方车；可以有多辆用户自主队伍。

## 第一位车头的流程

1. 从今天玩啥点击「我来发车」进入发布表单，或从大厅进入待发车详情后点击「我来发车」。
2. 接手使用独立的 `pages/publish/claim` 页面，可通过原生返回或「取消接手，返回」退出，不占用底部普通发车页，也不覆盖其草稿。自动带入推荐游戏、平台、21:00–23:00时间和人数，这些设置在接手时固定。
3. 用户必须填写房间号、Steam好友码或微信号，可填写密码、语音和备注，完成现有发车校验与内容安全检测。
4. 第一个成功提交完整表单的人担任车头；打开表单不预占车头位，也不会让空车变成有人。
5. 服务端事务在原队伍上写入车头及唯一车头成员，不创建第二辆车。并发竞争失败者返回队伍详情，作为普通乘客上车。
6. 后续成员沿用现有上下车和密码权限；车头可以补充集合信息、调整容量或散车，不能改推荐游戏及固定日程。

## 用户排行

- 发车榜：累计已完成发车的队伍数，系统尚未接手的空车不计。
- 上车榜：累计加入其他车头队伍的次数，同一用户同一队伍只计一次，重复上下车不增加；车头不重复算乘客。
- 两个榜单各前10名，TOP 10标识位于页面标题旁；前三名只在宝座展示，下方列表从第4名到第10名。领奖台与列表用户均可点击查看公开资料（昵称、头像、签名）。少于10人只显示真实人数，不造假数据；空榜显示邀请参与的提示。
- 使用完整分页数据统计，结合当前成员与已留存上车事件恢复历史。历史已退出且从未记录的上车无法追溯，不等于游戏实际到场次数。
- 封禁、资料失效用户不登榜。只返回昵称、头像、次数和不可逆标识，不返回OpenID、简介、联系方式或投票名单。

具体云函数、部署及验收见 [功能说明](./想玩投票与周五开黑.md)。本地验证不代表生产环境已生效。

## 页面与滚动

投票页去掉大幅介绍，保留紧凑的冠亚季军宝座，展示明确的「发起投票」入口、实时投票和用户发车；官方车仅在大厅及详情展示，详细规则默认折叠。大厅切换最新/最热时保留原列表直至排序结果返回，避免列表被清空后页面高度坍缩导致跳顶；真正切换筛选条件仍清空不匹配的旧结果。

发起投票通过弹窗输入游戏名称；成功后关闭，失败保留输入。全部用户共享当天游戏投票，同名游戏合并，不区分平台，每人每游戏一票。

今天玩啥与用户排行使用和发车页相同的自定义导航样式，依据状态栏及微信/QQ胶囊尺寸适配高度和标题留白，返回失败时回大厅。

投票页主操作使用固定底栏：左侧浅色「邀请群友投票」，右侧紫色「发起投票」；去掉标题旁及列表末尾的重复入口。列表预留底栏与安全区空间，编辑弹窗或资料补全弹层打开时隐藏底栏。
