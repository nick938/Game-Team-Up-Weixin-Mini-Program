# 今天玩啥、16点推荐车与用户排行

2026-10-21 更新。文件名与 `pages/friday/friday` 路径保留兼容，旧路径现展示「用户排行」，不再有每周或今晚开黑入口。

规则详见 [首页设计](./首页想玩与每日开黑设计.md)。

## 数据与接口

- `daily_play/{YYYY-MM-DD}` 存选项ID、16:00定榜结果、来源vote/history、选定游戏/平台/人数、唯一队伍ID。`play_options` 存私有创建者和投票记录。
- `getDailyPlay` 返回投票排名、本人意向、`settleAt/startAt/endAt`、推荐来源及队伍摘要，不返回创建者或投票者身份标识。
- `createPlayOption({ gameName, platform, requestId })`、`votePlayOption({ optionId, want })` 当天全天有效，同名同平台合并，用户可支持多个选项。每日最多50个选项并沿用频率限制。
- 复用 `startRemind` 每分钟定时任务，16:00后首次成功执行创建待发车，页面访问补偿漏跑。保持稳定ID `night_YYYY-MM-DD` 与日期索引事务锁，重复触发不重复建车。
- 历史样本通过完整分页扫描获取，只复制游戏、平台、容量，不复制旧车头、成员、房间信息、密码或联系方式。只在没有有效票时随机选择。
- 待发车：`dailyNightId`、`pendingHost:true`、`memberCount:0`，无openid、无members，roomNo为空。普通 `joinTeam` 拒绝跳过发车流程直接占位。
- `createTeam({ team, claimTeamId })` 接手原待发车，复用真实发布流程。服务端校验固定游戏、平台、日程和容量，要求有效联系方式，事务再次检查待发车状态，原子写入车头及唯一成员。相同车头重试幂等；其他竞争者收到CLAIM_TAKEN并返回详情上车。
- `getUserRankings` 返回累计hosted/joined各前10名，只包含昵称、头像、次数和哈希标识。按队伍去重，排除尚未接手空车、封禁/无昵称用户；上车数排除车头。读取teams/members/team_events/users完整分页数据。
- 每日推荐车保存officialSource=champion/random，API补齐旧版本标记，大厅和详情显示官方类型。普通发车不能传入或伪造该标记。
- 投票列表支持用户自己「发一车」，只带游戏信息进入普通发布表单，时间人数可编辑，不会占用或重建官方车。
- 新推荐局及已接手队伍继续在大厅显示，车头发车后进入「我的队伍」。23:00后不补建过期队伍；次日清空投票重新开始。

## 内容安全

新提议的游戏名、接手发车的用户文字均需微信 `msgSecCheck` v2明确pass才保存，review/risky、异常或缺失结果不放行。真实联系方式必填，不能使用「未知」「待填写」等占位内容。普通队伍、资料等旧入口的既有review/异常放行策略本次未统一改动，固定界面文案及历史数据也没有自动重审。

## 部署与验收

1. 部署包含lib的team云函数，确认daily_play、play_options、teams、members、team_events、users只经云函数按权限读写；启用现有startRemind定时器及security.msgSecCheck权限。配套更新小程序与QQ独立API契约。
2. 全天可提议多款游戏、同时想玩和取消；16:00仅冻结官方选车结果，实时榜单继续更新。并列、零票、没有历史、跨日与23:00过期情况正确。
3. 有票选榜首并沿用最近同游戏平台容量；无票从历史已完成队伍随机选，不选空车/已散/无效记录，不复制联系方式。
4. 生成车0人、无车头、无成员，显示待填写。直接调用joinTeam不能占位；点击接手进入独立可返回页面，预填表单且不能改固定字段，未填联系方式无法提交。
5. 两个账号同时提交，只出现一个车头和一条车头成员记录；相同提交重试不新增队伍或席位，失败者返回详情上车。成功后其他账号按普通流程加入，人数与我的队伍一致。
6. 检查榜单跨分页、前10与前三宝座、空榜、同票、重复上车去重、封禁用户过滤、头像转换及身份字段不泄露。
7. 检查取消接手后普通发车页和草稿恢复、排序不跳顶、320/375px、缩小入口与奖杯背景、官方随机/冠军标识、16点后投票不会更换官方车、投票列表自主发车、长游戏名/昵称、榜切换、列表失败重试和微信群分享。模拟API预览不代表真实云端持久化或真机通知送达。

本轮未自动提交、推送、部署云函数或发布小程序。
