## 配套部署顺序

1. 先部署 `cloudfunctions/team`，在云环境确认 `team_events` 集合及仅管理端读写权限。新集合由 `ensureCollections` 尝试创建；创建失败时需要在控制台处理。
2. 大厅按 endAt / expireAt / startAt 的未结束条件分批读取，并按 `_id` 稳定排序；若真实环境提示缺少索引，按错误提示创建所需索引并验证旧数据兼容。不得用截断结果伪装成全量搜索。
3. 用真实数据验证筛选、翻页、密码权限和多人操作，再发布配套微信前端。不要先只发布新前端，否则旧云函数会忽略新的筛选参数。
4. QQ HTTPS 后端须同步适配 `listTeams` 新参数/结果和 `trackTeamEvent`；QQ 编译成功不意味着后端已经可用。
5. 微信开发者工具和两台真机验证登录、昵称完善、分享落地、头像、订阅授权、消息实际送达和并发加入最后一个位置。

本次未执行云函数部署、体验版上传、提审、正式发布、Git 提交或推送。

## Wot 组件与玻璃材质改版

本轮按项目 `.agents/skills/wot-ui-v2/SKILL.md`，通过配置的 Wot MCP 服务（stdio）和 CLI 查询 2.3.2 文档，再对照实际 npm 源码核对接口。

- 大厅游戏分类、我的队伍分类、管理端分类使用 `wd-tabs` + `wd-tab`。
- 排序、未结束/历史、开始时间与时长使用 `wd-segmented`；不再用独立主按钮模拟分类。
- 详细筛选收进 `wd-popup`，保留全部搜索条件；先编辑草稿，确认时应用。
- 发车使用 `wd-form`、`wd-form-item`、`wd-select-picker`、`wd-collapse`，减少输入框与容器的重复边框。游戏名继续允许手填，选择器包含最近游戏和现有游戏目录。
- 底部采用原生 Tabbar；页面内继续使用 Wot 组件。玻璃材质集中在分段器与操作栏：半透明、背景模糊、高光边缘和轻阴影。无模糊支持时回退高不透明底色；支持减少透明度/动画的系统偏好。
- 操作栏通过 `wd-root-portal` 与明确的 CSS 安全区定位，发车栏距离原生 Tabbar 上缘 12px（H5 计入 `--window-bottom`，小程序由原生栏占用视口外区域），其他操作栏 12px + 安全区；避免无空格 calc 表达式与容器层级导致定位漂移。
- 发车操作栏随键盘与页面可见状态隐藏；弹层通过共享计数临时隐藏原生栏，最后一个弹层结束关闭动画后恢复。

验证结果：193 项测试通过；新增导航路由、弹层关闭后原生栏不复现、缓存页 onShow 时机的回归。七页分别以 320px / 390px 检查，无横向溢出、无页面脚本异常；三张 tab 页面各仅一套导航，其他页不残留导航；操作栏位置与 blur(24px) 计算样式符合预期。实际点击验证我的 Tabs/历史分段器，以及空表单提示必填且不请求发布。

微信开发者工具已加载新构建的大厅、发车页面；iPhone/Android 真机的模糊兼容性、性能与系统安全区仍需真机验收。这里实现的是跨端 CSS 玻璃材质近似，没有接入 Apple 系统级光学折射引擎。设计依据：[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)。

## 清缓存启动与切页加载感

用户确认底栏是在关闭欢迎弹窗之后出现。`welcome-letter` 通过共享弹层管理主动隐藏原生栏，直到 Popup 的 after-leave 才恢复；这不是原生栏晚渲染。已读标记被清缓存删除后会重新展示欢迎弹窗，此行为保留。回归覆盖首次隐藏、关闭动画结束后恢复，以及已读用户不再隐藏。

另外修复两处可确认的重复加载行为：大厅 onShow 在相同查询下保留上次成功结果，后台刷新并提示更新中，失败时标明显示旧结果；查询改变仍清空旧结果并保持响应防乱序。发车权限查询复用已有的 15 秒用户资料缓存与进行中的请求，避免启动、发车、我的短时间内重复请求 getProfile。

196 项测试通过；静态检查和微信/QQ/H5 构建通过。该证据证明行为与编译通过，未采集微信真机的切页耗时，不能断言原生导航变慢或声称已量化提速。未发布。
