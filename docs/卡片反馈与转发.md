# 队伍卡片反馈与转发

## 展示与互动

- 卡片保留游戏、人数（如2/4）、时间、车头、转发、真实浏览人数与反馈。平台、语音、还缺几人和常规招募状态留到详情；已散/已结束保留提示。
- 赞、踩、喜欢、下次一定全部互斥，每人每条车最多选择一个；切换会取消原选择，再点当前选项可取消。反馈不自动上车，不修改时间或订阅授权。
- 选择立即变紫并更新数量，失败回滚；允许连续点击，停止点击500ms后提交最终选择；回到原状态则不请求。请求串行，期间的新选择继续乐观显示，旧响应不会覆盖它；隐藏、卸载或换卡前提交待保存的选择，旧队伍响应不会写进新卡片。
- 转发按钮使用原生open-type=share，与卡片导航隔离。大厅、游戏列表、我的队伍将点击的具体队伍交给页面分享回调；用户排行分享达人榜；菜单分享仍使用页面原本的内容。
- 分享标题包含游戏、时间、人数，路径指向对应详情并标记from=share，封面使用现有品牌图兜底；不包含房间号、密码或成员身份。是否分享成功不作为浏览或上车证据。

## 单行反馈与动效

- 四个反馈同排，小屏保留44px点击区域，下次一定分配更多宽度，计数超过99显示99+。
- 点赞：10颗紫色/浅金色五角星局部炸开，550ms；踩：下压回弹和三条短线，300ms；喜欢：三颗小爱心上浮淡出，500ms；下次一定：本地透明鸽子图片序列扑翅并飞向右上方，750ms。
- 动效在乐观更新时立即播放；服务器响应只校准状态，不重播。取消只缩放回弹180ms，不重复放粒子。失败、切换队伍、页面隐藏和卸载都会清理动画；动画结束不会取消已选反馈。
- 粒子为局部透明图片与CSS变换，不参与布局、不接收点击。支持减少动态效果的环境隐藏粒子，只保留状态变化。不新增动画运行时依赖。

## 数据兼容

- 新setReaction请求传reaction与enabled（目标状态），重复请求幂等。selected数组最多返回一个选择，mine保留给旧客户端；counts保留旧表情键。
- like/love复用原含义；新增dislike/next（下次一定）。busy/time/fire/laugh/watch/game历史记录和计数保留，不重命名成新的态度或时间反馈；新界面不展示旧入口。
- 旧客户端不传enabled时仍按原单选接口处理。历史多选记录再次操作时，在事务内移除旧选择并校正计数；读取时仅高亮最后一个选择。
- team_views按队伍与真实调用身份的哈希生成唯一记录，事务内首次写入才增加teams.viewCount。详情访问和分享落地访问共享去重，跨天重访不重复增加。复制房间信息不增加浏览人数。
- 新统计从部署后开始，不用原watch手动票数冒充历史浏览量。接口只返回汇总人数，不返回浏览用户名单。

## 部署与验收

1. 先部署team云函数，确认team_views集合存在且仅管理端可访问；初始化会尝试创建。再更新小程序前端。旧云函数没有多维反馈和真实浏览统计。
2. 两个账号验证点赞/点踩切换、独立喜欢、下次一定选择、取消、重复提交、刷新恢复及失败回滚。
3. 同一账号从列表与分享两次打开详情，浏览人数只加1；另一账号打开再加1。旧围观数不影响浏览数。
4. 微信开发者工具或真机分别从大厅、游戏列表、我的队伍点队伍转发，群友打开应落到同一队伍；菜单分享仍分享原页面。用户排行页分享达人榜，落到用户排行页。
5. 检查320/375px卡片、长游戏名/昵称、全零反馈、满员和已结束/已散场景。浏览器模拟预览只能证明布局与模拟交互，不能证明微信分享、真实云端持久化或真实账号去重。
