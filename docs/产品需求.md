# 开黑星球｜游戏搭子 · 产品需求

更新日期：2026-10-19。本文描述当前源码的业务口径；源码实现、云函数部署、微信/QQ 真机验收与正式发布是独立环节。

## 1. 产品定位

帮助用户找到合适的游戏局，确认位置，加入后顺利进入游戏。主要路径为「发起队伍 → 分享到群或好友 → 进入队伍详情 → 加入 → 复制加入方式 → 打开游戏」。大厅同时支持主动找队伍。

保留大厅、发车、我的三个底部入口。暂不增加好友、动态、私信、语音房、付费、自动匹配、加入审批或踢人能力。

发布目标是微信小程序与独立 QQ 小程序。H5 仅用于本地开发和界面诊断。QQ 的 HTTPS 后端仍需适配并验证实际业务，不以编译成功作为可用证据。

## 2. 页面与元素

### 大厅

- 搜索游戏、区服、玩法要求、备注和来源群；最近使用游戏、常见游戏入口。
- 游戏筛选；开局时间、平台、只看可加入；更多筛选包含区服、语音、来源群。
- 默认只看可加入，可以关闭后查看满员队伍；全部结果中可加入优先，再按最新发布、最早开局或人数最多排序。
- 搜索、筛选、排序均由服务端处理；筛选结果再分页，每页 20 条，上限 50 条。计数为全部匹配队伍数。
- 切换条件重新请求第一页，丢弃过期请求；翻页沿用所有筛选条件。
- 已参加队伍的下一局提示，可回到详情。未来开局优先，若没有则显示仍未结束的局。
- 卡片展示游戏、还差人数、当前/总人数、开局时间、平台、区服、语音、玩法要求、发起人、来源群、我发起的/已加入标记。
- 空结果提供清空筛选与发布入口；选择的游戏可带入发车。请求失败展示重试，不当作没有队伍。

### 发车 / 编辑队伍

单页完成，不使用多步向导。

1. 玩什么：游戏名、最近使用与搜索建议、平台、区服。
2. 什么时候：现在/今晚/自定义、时长快捷选项、自定义 30 分钟至 24 小时。
3. 怎么进：包含发起人的总人数、必填加入方式、可选密码。
4. 补充要求折叠展示：语音、队友要求、备注、来源群。有代开权限时展示代开入口。
5. 底部固定发布/保存按钮；发布成功进入详情并突出分享招人。

- 游戏名仍支持任意手填；候选来自最近使用和现有游戏目录。
- 加入方式示例随平台变化；来源群仅作手填标签，不验证群身份，也不限制跨群加入。
- 编辑复用表单，最小人数不得低于当前成员数；可放弃编辑转为新建。
- 编辑加载失败禁止保存，提供重试；从游戏页进入新建时清除此前编辑身份。
- 普通发车和编辑遇到本人已有队伍时间重叠时，提醒后仍可继续；查询个人日程失败不阻断发布。代开不拿操作者日程约束被代开人。
- 再发一局刷新时间，保留配置并提示核对房间号与密码。

### 队伍详情

分享直接落地此页，无需先经过大厅。

- 游戏、人数、招募状态、开始与结束时间、组队条件、来源群、代开标识。
- 成员头像和昵称、发起人标识、空位、成员资料弹层。
- 公开加入方式及复制；密码按成员权限返回和展示。
- 备注、分享、举报、表情等辅助操作。
- 加入成功显示下一步进入游戏的说明，主要按钮改为复制加入方式。
- 队员主动选择是否申请开打提醒，不在加入前强制弹订阅授权。
- 开始/结束时间、平台、区服、加入方式或密码变化后，成员再次进入可见变更提示；只记录变更字段名称，未授权者不能读取密码值。

| 状态 / 身份 | 主要操作 | 辅助操作 |
| --- | --- | --- |
| 有空位的访客 | 加入队伍；已开始则提示中途加入 | 分享、举报 |
| 已加入队员 | 复制加入方式，进入游戏 | 分享、提醒、退出 |
| 未满的发起人 | 分享招人 | 管理队伍、查看进房信息 |
| 已满的发起人 | 复制加入方式 | 分享、管理队伍 |
| 满员的访客 | 去大厅查看其他队伍 | 下拉刷新 |
| 已结束 / 解散的发起人 | 去大厅查看队伍 | 再发一局 |
| 已结束 / 解散的队员或访客 | 去大厅查看其他队伍 | 查看历史信息、举报 |

### 游戏组队页

- 已选择游戏的大厅，游戏名称与介绍、匹配数量、搜索、同一套筛选/排序/分页与队伍卡片。
- 支持已知游戏别名查询，不再连续扫几页后在本地猜测是否存在队伍。
- 空结果可清空条件、发布当前游戏队伍；底部固定发车入口。
- 分享保留游戏参数；现有四个搜一搜落地页保持稳定路径。

### 我的与资料

- 头像、昵称、签名、编辑资料入口；资料编辑复用轻量弹层。
- 下一局提示，我发起的/我加入的，未结束/历史。
- 历史队伍可进入详情，发起人可再发一局。
- 帮助与反馈、社区公约、版本号；按身份展示代开或管理端入口。
- 浏览不要求先完善资料；发车、加入时资料不完整才引导填写昵称，头像和签名可后补。

### 帮助与反馈

- 常见问题：如何进游戏、满员/退出/结束、多个队伍、提醒、来源群、密码权限。
- 统一提供意见反馈、报错、联系作者、用户协议、隐私政策和社区公约入口。
- 反馈、报错、举报仍保留各自表单和服务端校验、限流、管理处理。

### 管理端

- 保留概览、队伍、用户、举报、报错、反馈。
- 可关闭队伍、封禁/解封、授予/取消组局员、处理举报/报错/反馈；云函数验证权限。
- 概览读取所有记录分批汇总，避免单次 get 截断为前 100/1000 条；近 7 天行为记录单独查询。
- 展示累计量、当前活跃、游戏排行、平台分布、近 7 天发车和组队效果，具体口径见第 5 节。
- 接入诊断仅为开发工具，不进入普通用户导航。

## 3. 队伍规则

| 项目 | 规则 |
| --- | --- |
| 必填 | 游戏、开始时间、结束时间、总人数、房间/加入方式 |
| 人数 | 整数 2–20，包含发起人；不能重复占位 |
| 时间 | 结束晚于开始且晚于现在，时长最长 24 小时，开始在未来 7 天内；允许已经开始但未结束 |
| 招募状态 | 招募中、满员、已解散、已结束 |
| 时间阶段 | 未开始、已开始，独立于招募状态；已开始但未结束且有空位时允许中途加入 |
| 满员 | 禁止新成员加入；队员退出且未结束时自动恢复招募 |
| 并发 | 加入使用事务；编辑在事务内重新校验结束/解散、当前人数与更新版本，避免覆盖新加入人数或冲突编辑 |
| 多个队伍 | 允许同时发起/加入多个队伍，时间重叠为可取消或继续的提示 |
| 退出 | 队员可退出，发起人只能解散整局 |
| 结束 | 到结束时间自然过期，读取时计算，不依赖客户端写状态 |
| 加入方式 | 所有人可见，密码仅按成员身份下发 |
| 密码 | 发起人始终可查；队员在未解散时可查；分享卡片不带密码 |
| 来源群 | 选填，规范化空白与全角字符，上限 24 字，不代表已验证的微信群 |
| 代开 | 管理员/组局员搜索资料完善且未封禁的用户，由对方担任发起人 |

## 4. 提醒与分享

- 加入不依赖订阅授权；详情为已加入成员提供可选授权入口。
- 微信授权成功仅说明获得本次授权，不等于消息已发送或送达；QQ 不请求微信订阅模板。
- 现有提醒定时器保留：开始前约 10 分钟发送，同一局按收件人处理结果，临时失败在窗口内重试。开始前 10 分钟内才加入可能赶不上提醒。
- 解散后尝试通知有可用订阅额度的成员，发送失败不影响关闭队伍。
- 分享保留队伍 ID，并添加 `from=share` 作为访问来源标记。此标记是分析信号，不是权限凭据。
- 分享卡片封面保留动态渲染与静态品牌图回退，禁止出现空白封面。
- 朋友圈单页预览不发起业务请求、不写欢迎或最近游戏记录。

## 5. 统计口径与存储

- `teams`、`members`、`users` 等现有集合继续使用；新增 `team_events`。
- 详情访问、分享入口访问、成功加入、成功复制加入方式记行为事件。记录用户标识、队伍 ID、事件类型和时间，不记录剪贴板正文；不在普通用户页面下发。
- 事件 ID 按日期（UTC+8）+用户+队伍+类型计算，重复操作同日覆盖，不等于点击次数。行为接口校验队伍、类型、封禁和限流。
- 行为统计失败不阻断详情展示、复制或加入。历史版本没有的事件不补造数据。
- 近 7 天发布：过去 7×24 小时创建的队伍数量。
- 目前有队员加入 / 目前满员：上述队伍的当前人数大于 1 / 达到容量；退出会改变结果，不是历史累计成功率。
- 分享入口访客：近 7 天有分享访问记录的用户-队伍组合数。
- 分享访客中有加入记录：上述组合中同时存在近 7 天成功加入记录的数量。仅为关联，不作为严格的因果转化率。
- 复制加入方式：近 7 天的用户-队伍-日期去重记录数，**不能代表实际进入游戏或实际开打**。
- 当前成员记录含发起人；退出会删除记录，所以不能称为累计上车人次。

## 6. 部署与验证

- 前端与 `team` 云函数必须配套部署，QQ HTTPS 后端需适配同一请求契约。
- `team_events`、`team_reactions` 等业务集合保持仅管理端读写，普通客户端通过云函数调用。
- 大厅服务端按未结束条件读取候选，包含缺少 endAt 的旧记录；分批读取后筛选、排序、统计并分页。当前不再设置隐藏的 200 条扫描上限。
- 当前方案适合小规模组队数据。候选队伍大幅增长时，应将搜索字段与排序进一步下推数据库索引或专用检索，而不是添加静默截断。
- 若云环境提示查询缺少索引，按控制台错误为 endAt/expireAt/startAt 与 _id 查询配置所需索引，再完成真实数据搜索与翻页验收。
- 本地测试、浏览器测试数据预览、构建、云端部署和真机操作分别记录，不能互相代替。
