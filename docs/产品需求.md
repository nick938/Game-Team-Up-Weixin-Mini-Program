# 开黑星球｜游戏搭子 · 当前产品说明

更新日期：2026-10-22。描述当前源码行为；部署、体验版验收和正式发布分别确认。

## 页面与入口

底部为大厅、发车、我的。大厅进入今天玩啥和用户排行；车辆卡片、个人队伍记录或分享进入详情；待发车可进入独立接手页。详情提供同游戏入口，游戏页也用于搜索/分享落地。

我的提供个人资料、发起/加入的队伍、设置、帮助、更新公告与更新日志。设置/帮助提供协议、反馈与报错；车辆详情提供举报；管理员在我的进入管理端。页面注册和实际来源见 [README](../README.md)。

## 大厅与卡片

- 搜索游戏、区服、玩法要求和备注；支持游戏、群组、开局时间、区服、语音、只看可加入及排序。游戏平台字段仅保留兼容，不提供平台筛选入口。
- 默认包含满员车辆；开启只看可加入后仅展示有位置且可加入的车。可加入优先，再按最新发布、最早开局或人数排序。
- 服务端筛选后分页，默认20条、上限50条。切换条件清空旧结果并重置分页；相同条件刷新或切换排序可保留列表直至请求返回，丢弃过时响应。
- 卡片展示游戏、人数、开局时间、车头、群组及官方车标识；点击进入详情。赞、踩、喜欢、下次一定每人每车一个，可切换或取消；立即更新展示，停止点击500ms后提交，失败回滚。
- 浏览次数统计每次成功进入详情或分享详情的访问，包含重复访问；不是独立访客数。行为事件另按上海日期、用户、车辆及类型去重，不等于实际进游戏次数。

## 发车、编辑与上下车

| 项目     | 规则                                                                                |
| -------- | ----------------------------------------------------------------------------------- |
| 必填     | 游戏、开始/结束时间、包含车头的总人数                                               |
| 人数     | 2–20的整数，不能重复占位；编辑容量不得低于现有人数                                  |
| 时间     | 结束晚于开始和现在，时长最长24小时，开始不超过未来7天；已开始但未结束且有空位可加入 |
| 备注     | 发布/编辑/接手表单不提供备注输入，新提交为空                                        |
| 招募     | 招募中、满员、已散、已结束；开始阶段与招募状态独立                                  |
| 并发     | 上车、编辑、接手官方车在事务内校验状态和人数                                        |
| 日程     | 可同时发布/加入多车；时间重叠提示后可继续                                           |
| 退出     | 队员退出，有位置且未结束则恢复招募；车头只能散车                                    |
| 加入方式 | 发布/编辑/接手表单不提供联系车头及密码输入，新提交为空；旧记录密码仍按成员权限返回  |
| 代开     | 管理员/组局员可为资料有效、未封禁的目标用户发车，由目标用户担任车头                 |

本次按发布页截图移除联系车头、房间密码、备注输入组件（非 CSS 隐藏），提交时将这些字段及旧区服/要求置空，避免旧草稿和历史车辆带入隐藏内容；编辑保存也会清空这些字段。游戏名等其他自定义入口仍保留，不代表已完成个人主体审核整改。

普通发车保留草稿和近期游戏设置；编辑、新建、再发一局相互区分。发布成功进入详情，分享招人；加入成功按现有记录提供加入方式及打开游戏入口；新车不再通过发车表单提供联系方式。小程序不自动进入游戏。

## 车辆分享与提醒

- 列表转发和详情分享使用同一车辆标题、详情链接和5:4信息图：缺人/满员等状态、游戏、时间、当前/总人数及语音/区服等标签，不显示游戏平台标签，不带房间号和密码。
- 图片复用旧版车辆邀请卡样式；绘图失败使用品牌图，右上角菜单分享保留各页面自身内容。
- `from=share` 仅标记访问来源，不是权限凭据；朋友圈单页预览不发起业务请求或写本地欢迎状态。
- 微信分享事件必须由页面入口直接注册，维护要求见 [AGENTS.md](../AGENTS.md)；原生构建自动检查注册标记。
- 加入不依赖订阅授权；成员可自愿申请开打提醒。微信授权、云端发送和实际送达分别确认；QQ 不请求微信订阅模板。
- 现有 `startRemind` 定时器在开始前约10分钟提醒，按收件人记录结果并在窗口内重试临时失败；太晚上车可能错过扫描。散车尝试通知有额度的成员，发送失败不阻断散车。

## 个人资料与群组

- 浏览无需完善资料；发布或加入时引导补齐昵称，头像、签名和其他字段可后补。
- 昵称、头像、签名、群组、常玩游戏、常玩时间、Steam好友码和微信ID为明确公开字段；排行榜与成员抽屉均展示已填写内容，未填写不显示。
- 群组最多10个、常玩游戏最多5个且每个最多40字、时间段最多5个。Steam好友码为最多20位数字字符串，保留前导零；微信ID最多32位字母、数字、下划线或短横线。
- 保存未传字段时保留旧值；空数组/空字符串表示主动清空。联系方式可点击图标或长按复制。
- 群组是标签，不限制跨群上车。发布/代开/接手时由服务端复制实际车头群组，客户端不能伪造；之后改资料不会追改旧队伍。筛选多个群组时任意匹配。
- 选项维护源为 `cloudfunctions/team/lib/profile-options.json`，维护步骤见 [维护与验收](维护与验收.md)。

## 今天玩啥与官方推荐车

- 按上海时区每日独立；全天可提议、投票及取消，每人每游戏一票，可支持多个游戏。规范化后同名游戏合并，不区分兼容平台字段；每天最多50个选项。
- 每日16:00定官方选车结果，固定21:00–23:00；随后实时票数继续变化，不更换已定车辆。
- 有票取票数最高者，并列按提议时间及稳定标识；容量沿用同游戏、同兼容平台最近有效历史车，无匹配默认4人。无有效票则随机参考有效历史车；没有历史不虚构车辆，23:00后不补建过期车。
- 官方车开始为0人、无车头/成员、无联系方式，标为冠军车或随机车。首位通过独立接手表单确认的人，在事务中成为唯一车头；只打开表单不占位，不能直接上车绕过接手。
- 接手固定推荐游戏、平台、时间和初始容量，仅保留语音选择，联系方式/密码/备注不提供输入且提交为空；并发失败返回原车详情。同一车头重试不增加成员。
- 投票选项的「发一车」只预填游戏信息，进入普通发车流程，不受官方固定日程/人数约束，也不占官方车。
- `daily_play` 保存每日选车结果，`play_options` 保存选项及私有票记录；`startRemind` 定时任务和页面访问共同补偿定榜，稳定ID及事务避免重复建车。

## 用户排行与管理

- 发车榜：累计已完成发车的队伍数，未接手系统空车不计。上车榜：累计加入其他车头的队伍数，同人同车只算一次，车头不重复算乘客。
- 各榜前10，前三名领奖台，列表从第4名起；仅展示真实用户。使用完整分页的队伍、成员、上车事件和资料，兼容 `_id` / `openid` / `_openid`；旧退出记录未留事件的无法追溯。
- 封禁/无昵称用户不登榜；返回公开资料及哈希标识，不公开原始身份、订阅偏好和投票者名单。
- 管理端包含概览、队伍、用户、举报、报错、反馈；可强制散车、封禁/解封、设置组局员和处理记录。入口隐藏不代替服务端权限验证。
- 举报/报错/反馈的提交人显示最新昵称，举报车头优先昵称，缺失时回退OpenID；用户管理卡片保留OpenID供配置核对。
- 反馈、报错、举报经过现有内容校验与限流；封禁用户可浏览，写操作被服务端拒绝。

发布与真机检查统一维护在 [维护与验收](维护与验收.md)，不再保留分散的已完成实施清单和过期测试数量。
