# 图一乐游戏组局助手 · 产品需求

> 版本：v1.6.1  
> 日期：2026-09-10  
> 范围：微信小程序 + 微信云开发  
> 状态：功能完整已落地（订阅消息已接「游戏组局即将发车」模板；新增管理端、举报、报错、防刷与数据统计）  
> 产品名：**图一乐游戏组局助手**  
> 简称：**图一乐**

---

## 1. 产品是什么

给微信里想一起玩游戏的人用的组队工具。主要面向 Steam / 手游 / 端游 / 主机联机。

发起人发一条组队信息（玩什么、什么时候、几缺几、怎么进），把卡片分享到微信群或私聊。别人点开就能看详情、一键加入。人齐了开打，到结束时间自动散。

不做游戏本身，不做语音房，不做公会。只做「发车 → 分享 → 上车 → 开打」。

一句话：**微信里的开黑发车板。**

对外名称用 **图一乐游戏组局助手**，任务栏、分享卡片简称 **图一乐**。分享卡片：「图一乐｜CS2 还差 2 人 · 21:00」。不像游戏发行方，也不像工具后台。

---

## 2. 要解决的问题

现在大家组队靠群里喊、朋友圈、截图房间号。问题是：

- 信息散，过几分钟就被刷掉
- 房间号、人数、时间写在不同消息里，对不上
- 新人进群不知道还有没有位置
- 分享出去的人看不到「现在几缺几」

这个小程序把一条车的信息、人数、状态钉在一个可分享的页面上。

---

## 3. 目标用户

| 角色 | 是谁 | 典型场景 |
| --- | --- | --- |
| 车头（发起人） | 想凑一局的人 | Steam 上差 2 个打 CS2，发到群里等人 |
| 乘客（加入者） | 看到分享或在大厅闲逛的人 | 点链接上车，或按游戏名找车 |
| 路人 | 第一次打开小程序 | 浏览正在进行的车，决定加不加 |

**分享进群是主路径，大厅是辅路径。** 首期不做陌生人社交匹配算法。

---

## 4. 核心场景

### 4.1 发车并拉人（主路径）

1. 车头填写：游戏、平台、开始/结束时间、人数、进房方式、语音等
2. 发布成功，进入队伍详情
3. 点「丢给好友」，发到微信群或私聊
4. 群友点卡片进入详情，点「上车」（无需车头同意）
5. 人数满了，状态变为「满员」，不能再加
6. 有人下车则回到「缺人」
7. 到结束时间自动变为「已结束」，不能再加入

### 4.2 接受邀请

1. 用户从分享卡片进入，落到**这一条队伍**的详情，而不是首页
2. 未填昵称时，先填写再加入（头像可选）
3. 已满、已散、已结束时，说明原因，并给「看看别的车」入口

### 4.3 自己找车

1. 打开大厅，看到未过期的队伍（缺人优先，满员仍展示）
2. 可按游戏名筛选
3. 自己的车、已上车的车有标记
4. 点进详情，加入或分享给别人

### 4.4 再来一趟

车头把上一趟的游戏、人数、进房方式、备注等带进发车表单，时间改到最近，直接再发。

## 5. 组队信息（一条车里有什么）

### 5.1 必填

| 字段 | 说明 |
| --- | --- |
| 游戏名 | 手填，≤ 40 字。无内置游戏列表 |
| 开始时间 | 日期 + 时间。允许已经开始、尚未结束 |
| 结束时间 | 必须晚于开始时间，且晚于现在。一局最长 24 小时。到点即过期 |
| 需要人数 | 含车头。默认 5，范围 2–20 |

### 5.2 选填

| 字段 | 说明 |
| --- | --- |
| 怎么进 | 房间号 / Steam 好友代码 / 房间码。**未加入也直接显示**。≤ 80 字 |
| 进房密码 | 仅**已加入成员**可见（车头始终可见，便于再发一趟） |
| 平台 | Steam / 手游 / 端游 / 主机。默认 Steam |
| 区服 | 自由文本，如 欧服、微信区。≤ 20 字 |
| 语音 | 不限 / **KOOK** / 游戏内语音 / 开麦。国内用户默认常用 KOOK |
| 水平 | 自由文本，如「娱乐局、上分」。≤ 20 字 |
| 备注 | 玩法、麦序、怎么加好友。≤ 80 字 |

### 5.3 系统生成

| 字段 | 含义 |
| --- | --- |
| 队伍 ID | 用于分享路径 |
| 车头 | 发布者 OpenID、昵称、头像 |
| 当前人数 / 缺几人 | 实时 |
| 状态 | 见第 7 节 |
| 创建时间、过期时间 | **过期时间 = 结束时间** |

## 6. 功能范围

### 6.1 第一期（P0）— 已验收

- 微信身份：OpenID；发车/加入前填写昵称（头像可选）
- 发布组队；未过期前车头可编辑
- 关闭这趟（车头）；队员可下车
- 队伍详情：成员、缺几人、进房方式（公开）
- 直接上车 / 下车，无需审批
- 分享到微信聊天（卡片带队伍 ID，落地详情页）
- 大厅列表（未过期、未取消）
- 「我的」：我发的车、我上的车
- 状态：缺人 / 满员 / 已散 / 已结束
- 进房方式公开；进房密码仅队员可见
- 可同时开多趟、加多趟。同一趟局里不能重复占两个位置

### 6.2 功能完整（本期）— 已落地

- 大厅给自己的车 / 已上车打标；缺人排在满员前面
- 大厅按游戏名筛选
- 「我的」把进行中和已结束分开
- 车头「再发一趟」（沿用上一趟信息，时间刷新）
- 用户协议 / 隐私政策 / 社区公约
- 订阅消息：每局最多一条。默认「即将开打」（开始前 10 分钟）；若车头提前散了这趟，已订阅的成员改为收到「这趟散了」。不再发送「有人上车 / 人齐了」（模板：游戏组局即将发车）
- 首次进入展示一封欢迎信（友好相处 / 社区公约）；「我的」可再次打开公约
- 一局最长 24 小时
- 「我的」意见反馈：模板填写后发到开发者邮箱；页脚显示版本号

### 6.2.1 运营与管理（本期新增）— 已落地

- 举报入口：队伍详情页对非车头开放，理由选项 + 补充说明，24 小时内同一目标不重复受理
- 用户报错： 「我的」页脚入口，模板填写 + 可选错误信息，自动附带页面、版本、设备信息；前端未捕获异常由 `app.onError` 记录并预填
- 防刷限流：发车、上车、举报、报错按「动作 + 用户」在时间窗内计数，超限拒绝
- 管理端：概览、组队、用户、举报、报错、反馈六个标签；概览含核心指标与最活跃游戏排行；组队页可强制关闭任意进行中的队伍；用户页可封禁 / 解封
- 版本号：正式版取微信后台上传的版本号，开发版/体验版取代码里的 `APP_VERSION`，两者允许不同
- 数据统计：按游戏聚合进行中/总场次/上车人次并打分排序，另有平台分布与近 7 天发车趋势

### 6.3 明确不做 / 以后再做

- 车头审批加入
- 车头踢人（一起玩就该开开心心；上车的人可自行下车）
- 应用内提醒开关（真正的开关是微信订阅授权，关闭请到微信小程序设置）
- 即时聊天、语音、视频
- 好友、关注、私信
- 游戏账号 / 战绩校验
- 付费、匹配推荐
- 朋友圈分享
- 「发车中」手动按钮（到结束时间自动过期）
- 小程序码
- 队伍留言板

## 7. 队伍状态

```
招募中 ──人满──► 已满员
   │               │
   │               │有人退出且未到结束时间
   │               ▼
   │            招募中
   │
   ├──车头取消──► 已取消
   └──到结束时间──► 已过期
```

没有单独的「进行中」状态。开始时间已过、结束时间未到，仍按人数显示缺人或满员，并打上「进行中」标记：不隐藏（允许「现在开打」和长局），但在大厅沉底、排到未开始的车之后，避免冒充招募中。详情页对这类车显示「中途加入」。

| 状态 | 能否加入 | 分享卡片 |
| --- | --- | --- |
| 招募中（缺人） | 能 | 「图一乐｜游戏名 还差 N 人 · HH:mm」 |
| 已满员 | 不能 | 「图一乐｜游戏名 已满员」 |
| 已取消 | 不能 | 「图一乐｜游戏名 已散」 |
| 已过期 | 不能 | 「图一乐｜游戏名 已结束」 |

车头占 1 个位置。满员与招募中随人数自动切换。

「进行中」= 状态为招募中或已满员，且当前时间未到结束时间。

## 8. 权限

| 动作 | 车头 | 已加入成员 | 未加入访客 |
| --- | --- | --- | --- |
| 看游戏、时间、缺几人、备注 | ✓ | ✓ | ✓ |
| 看完整进房方式 | ✓ | ✓ | ✓（直接显示） |
| 看进房密码 | ✓ | ✓（未散时） | 不可见 |
| 加入 | — | — | 招募中且未满 |
| 退出组局 | 不可退出，只能关闭整局 | ✓ | — |
| 编辑信息 | 进行中 | — | — |
| 关闭组局 | ✓ | — | — |
| 再发一趟 | ✓ | — | — |
| 分享 | ✓ | ✓ | ✓（进行中） |
| 举报这趟车 | — | ✓ | ✓ |

约束：

- 同一用户同一条队伍只能加入一次
- 进行中作为车头可开多趟
- 进行中作为队员可加入多趟；同一趟局不能重复加入
- 开始时间可早于现在，结束时间必须晚于现在；开始须在 7 天内

## 10. 页面结构

```
大厅（tab）
  ├─ 进行中的车（缺人优先，满员仍展示）
  ├─ 按游戏名筛选
  └─ 发车入口（空状态）

发车（tab，发布表单）
  └─ 成功后进详情；也可从「再发一趟 / 编辑」带入

队伍详情（分享落地页，非 tab）
  ├─ 状态、缺几人、进房方式
  ├─ 成员
  └─ 加入 / 退出 / 分享 / 车头操作 / 再发一趟

我的（tab）
  ├─ 头像昵称
  ├─ 我发起的：进行中 / 已结束
  ├─ 我加入的：进行中 / 已结束
  ├─ 意见反馈（模板 → 开发者邮箱）
  ├─ 报个错（模板 + 错误信息 → 管理端）
  ├─ 管理端（仅管理员可见）
  └─ 用户协议 / 隐私政策 / 社区公约 / 版本号

举报（分享落地页内的二级页，非 tab）
  └─ 理由选项 + 补充说明 → 提交举报

报个错（非 tab）
  └─ 出问题页面 + 现象 + 错误信息 → 提交

管理端（非 tab，仅管理员）
  ├─ 概览：核心指标 + 最活跃游戏 + 平台分布 + 近 7 天趋势
  ├─ 组队：进行中的队伍，可强制关闭
  ├─ 用户：搜索 / 只看已封禁 / 封禁 / 解封
  ├─ 举报：按未处理筛选 / 标记已处理
  ├─ 报错：按未处理筛选 / 标记已处理
  └─ 反馈：按未处理筛选 / 标记已处理
```

| 字段 | 含义 |
| --- | --- |

管理员名单，`_id` 为管理员 OpenID。也可改用云函数环境变量 `ADMIN_OPENIDS`（逗号分隔）。

写操作全部走云函数 `team`。加入用事务，防止超员。

## 12. 关键流程

### 发布

校验必填、结束时间在未来、时长 ≤ 24 小时 → 写 teams + 车头 member → 跳转详情。请求订阅消息。

### 加入

校验招募中、未满、未过期、未重复 → 事务写入 → 满员则 status=full。请求订阅消息（额度预留给开打提醒）。不通知车头。

### 退出

删 member → memberCount-1 → 未过期则满员改回招募中。

### 取消

仅车头；status=cancelled。给车上其他成员发「这趟散了」（占用各自的一次性订阅额度，替代开打提醒）。

### 过期

懒过期：`now >= endAt` 视为已过期。列表查询 `endAt > now` 且未取消。

### 开打提醒

定时每 1 分钟扫一次。开始时间落在「现在起 10 分钟内」且未过早（含刚过点 5 分钟）的进行中队伍，给车上所有人发「即将开打，请准时上线」，并写下 `startRemindedAt`；同一趟内按收件人记录结果，暂时失败的窗口内每分钟补发，全部处理后标记整趟已提醒。开打前 10 分钟内才上车的人错过本轮扫描，不再补发。

### 再发一趟

带入游戏名、人数、进房方式、平台、语音、备注等；开始/结束时间按默认（约 1 小时后开始，默认打 2 小时）。发布为新队伍。

### 意见反馈

校验类型、页面、正文（不能只交空白模板）→ 写入 feedback → 发到开发者邮箱。同一用户 2 分钟内不可连发。不收集联系方式等身份信息（合规要求）。

### 举报

详情页选理由（+可选补充）→ 校验目标队伍存在、理由合法、内容安全 → 同一用户 24 小时内对同一队伍不重复 → 写入 reports（kind=report），记录车头 OpenID → 管理端处理。

### 报错

「我的」选页面、填现象（+可选错误信息）→ 校验页面合法、正文非空白模板、内容安全 → 5 分钟内最多 3 条 → 写入 reports（kind=bug），附带版本与设备信息 → 管理端处理。

### 防刷

写接口在执行业务逻辑前读 `rate_limits` 中「动作_OpenID」的时间窗记录，达到上限即拒绝并返回提示；成功后追加当前时间戳。记录读写失败不阻断主流程。

### 数据统计

管理端拉取 teams / users / members / reports / feedback，按游戏聚合进行中、总场次、上车人次，按 `active×3 + teams + members÷2` 打分排序取前 10；同时统计平台分布与近 7 天发车趋势（按 UTC+8 归日）。

### 管理端强制关闭

管理员在「组队」页看到进行中的队伍 → 二次确认 → `adminCancelTeam` 校验管理员身份与队伍状态 → 标记 `cancelled` 并写 `cancelledBy: "admin"` → 通知车上所有人（含车头），与车头散局通知同一套逻辑。

### 封禁 / 解封

管理员在「用户」页搜索目标 → 封禁（可填原因）→ `adminSetBan` 校验身份、禁止封禁自己与管理员 → 写 `users.banned`。被封禁账号的写操作（发车 / 上车 / 改资料 / 反馈 / 报错 / 举报）在云函数统一拒绝并返回 `code: "BANNED"`，浏览不受限。解封时清空原因与时间。

## 13. 体验细节

- 卡片一眼能看到：游戏名、时间段、`3/5`、还差几人、进房方式
- 1 小时内开打标「即将开始」
- 自己的车、已加入的车，大厅打标记
- 进房方式、密码可复制
- 空状态引导发车
- 首次打开弹出欢迎信；点确认后不再出现
- 分享进来已满：说明原因 + 「看看别的车」
- 时间展示为「今天 21:00–23:00 / 明天 14:00」
- 人数步进器，默认 5，范围 2–20
- 语音选项以 KOOK 为主（国内），不做 Discord
- 「我的」显示版本号；意见反馈带模板，发送到开发者邮箱
- 管理员可见管理端入口；概览用横向进度条展示游戏活跃度，柱状图展示近 7 天趋势

## 14. 内容与合规

- 备注 ≤ 80 字，进房方式 ≤ 80 字，自定义游戏名 ≤ 40 字
- 云函数本地违禁词 + 微信 `msgSecCheck` 文本检测（仅拦 risky）
- 「我的」提供用户协议 / 隐私政策 / 社区公约
- 类目走社交或工具，不挂游戏
- 头像昵称用官方 `chooseAvatar` + `type=nickname`，不用 `getUserInfo`
- 头像上传云存储后由云函数下载并过 `security.imgSecCheck`；未通过的图片会删除并拒绝保存
- 进房密码未加入不下发；已散后仅车头仍可见（便于再发）
- 举报理由与报错正文同样过本地违禁词与 `msgSecCheck`；举报记录留存车头 OpenID 供追溯
- 报错会附带设备与基础库信息，用于定位；不额外收集手机号等联系方式

## 16. 验收

第一期 10 条仍有效，并增加：

1. A 发一趟 CS2、今晚 9 点到 11 点、5 人、好友代码；未加入的人也能看到进房方式
2. A 把卡片发到聊天，B 点开落在这条详情
3. B 填昵称后加入，看到密码（若有），人数 2/5
4. 满员后其他人加入失败
5. 有人退出后恢复招募中
6. A 能改信息、散了这趟
7. 大厅能看到进行中的车；自己的车 / 已上车有标记；可按游戏名筛
8. 「我的」里发起/加入分开，进行中和已结束分开
9. 到结束时间后不能再加入；开始已过、结束未到仍可加入（未满时）
10. A 可同时开多趟；B 可同时加入多趟；同一趟不能重复加入
11. A 点「再发一趟」，表单带上局信息，时间已刷新
12. 「我的」能打开用户协议、隐私政策和社区公约
13. 配置订阅模板后：A 散了这趟，B 能收到「这趟散了」；B 已授权时，开打前能收到「即将开打」
14. 开打前 10 分钟，车上已允许通知的人收到「即将开打，请准时上线」；开打前 10 分钟内才上车的人不补发
15. 发车或改时间后，开始到结束超过 24 小时会被拒绝；刚好 24 小时可以发
16. 第一次打开小程序会看到欢迎信；确认后再次进入不再弹出
17. 「我的」能看到版本号，能打开意见反馈；按模板填写后可提交
18. 配置发信后，反馈会进入开发者邮箱；未配置发信时仍会写入 feedback 集合
19. 非车头在详情页可举报这趟车；理由必选，24 小时内重复举报同一趟会被拒
20. 「我的」能打开「报个错」；空白模板被拒，填写后可提交，错误信息随记录保存
21. 短时间内反复发车 / 上车 / 举报 / 报错会触发限流，被拒后提示「太频繁」
22. 管理员在「我的」可见管理端入口，非管理员进入提示「没有管理权限」
23. 管理端概览能看到累计组队、进行中、待处理数量；最活跃游戏排行与近 7 天趋势按数据正确展示
24. 管理端能把举报 / 报错 / 反馈标记为已处理，并可切回未处理
25. 管理端「组队」页能看到进行中的车，强制关闭后状态变为已散、车上成员收到「这趟散了」
26. 车头管理菜单没有「再发一趟」；散局仍只允许车头
27. 「我的」版本号：正式版显示微信后台上传的版本号，开发版显示本地 `APP_VERSION`，两者允许不同
28. 管理端「用户」页可搜昵称 / OpenID、只看已封禁；封禁后该用户的发车 / 上车 / 反馈 / 报错 / 举报全部被拒，仍可浏览大厅与详情
29. 封禁自己或封禁管理员会被拒绝；解封后写权限恢复
