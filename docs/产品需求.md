# 开黑星球｜游戏搭子 · 当前产品说明

更新日期：2026-11-26。描述当前源码行为；部署、体验版验收和正式发布分别确认。

## 页面与入口

底部为首页、发车、我的。首页队伍列表支持单栏和双栏瀑布流，记住上次选择。「我的 → 设置中心」可选跟随系统、浅色或深色，记住上次选择。微信与 H5 默认跟随系统，QQ 无系统主题时默认浅色。微信使用悬浮液态玻璃风格底栏，支持点按及横向拖动切换，拖动时胶囊抬升放大，松手后吸附回弹；弹层关闭后恢复显示；发车提交按钮位于底栏上方。大厅将排行入口放在搜索与筛选右侧，当前招募或即将开局的队伍显示在搜索上方；车辆卡片、个人队伍记录或分享进入详情；待发车可进入独立接手页。详情提供同游戏入口，游戏页也用于搜索/分享落地。QQ/H5 保留原底栏和「今天玩啥」页面，实际服务取决于各自的 HTTPS 后端。

「我的」提供个人资料和队伍记录，并可直接打开设置中心、常见问题、意见反馈、报错、更新公告、协议与隐私。设置中心提供外观切换。常见问题提供联系作者入口，协议与隐私页可切换用户协议、隐私政策和社区公约，更新公告可打开更新日志。管理员在「我的」进入管理端。页面注册和实际来源见 [README](../README.md)。

## 首页与卡片

- 搜索游戏、区服、玩法要求和备注；支持游戏、群组、开局时间、区服、语音、只看可加入及排序。游戏平台字段仅保留兼容，不提供平台筛选入口。
- 默认包含满员车辆；开启只看可加入后仅展示有位置且可加入的车。可加入优先，再按最新发布、最早开局或人数排序。
- 服务端筛选后分页，默认20条、上限50条。切换条件清空旧结果并重置分页；相同条件刷新或切换排序可保留列表直至请求返回，丢弃过时响应。
- 卡片展示游戏、人数、开局时间、车头及官方车标识；单栏布局在人数旁显示群组名称，双栏布局隐藏群组标签，多个群组显示首个名称和其余数量，完整名称在队伍详情展示；标题和群组名能放下时同排，空间不足时先将群组名换到下一行，人数始终显示在右上角。下次一定用鸽子图标，点按反馈选中或取消，长按可查看含义。赞、踩、喜欢、下次一定每人每车一个，可切换或取消；立即更新展示，停止点击500ms后提交，失败回滚。
- 浏览次数统计每次成功进入详情或分享详情的访问，包含重复访问；不是独立访客数。车辆卡片的转发计数累计发起聊天分享的次数，包含从列表和详情发起的分享，发送状态不计。行为事件另按上海日期、用户、车辆及类型去重，不等于实际进游戏次数。

## 发车、编辑与上下车

| 项目     | 规则                                                                                |
| -------- | ----------------------------------------------------------------------------------- |
| 必填     | 游戏、开始/结束时间、包含车头的总人数                                               |
| 人数     | 2–20的整数，不能重复占位；编辑容量不得低于现有人数                                  |
| 时间     | 结束晚于开始和现在，时长最长24小时，开始不超过未来7天；已开始但未结束且有空位可加入 |
| 备注     | 发布/编辑/接手表单不提供备注输入，新提交为空                                        |
| 招募     | 招募中、满员、已散、已结束；开始阶段与招募状态独立                                  |
| 并发     | 上车、编辑、接手官方车在事务内校验状态和人数；事务冲突自动退避重试，仍失败时提示稍后再试 |
| 日程     | 可同时发布/加入多车；时间重叠提示后可继续                                           |
| 退出     | 队员退出，有位置且未结束则恢复招募；车头只能散车                                    |
| 加入方式 | 发布/编辑/接手表单不提供联系车头及密码输入，新提交为空；旧记录密码仍按成员权限返回  |
| 代开     | 管理员/组局员可为资料有效、未封禁的目标用户发车，由目标用户担任车头                 |

发布、编辑和接手表单均移除语音选择。普通发车、代开、再发一局和接手不提交语音偏好，服务端默认「不限」；旧车编辑保存时沿用已存语音字段，历史标签和固定车设置继续兼容。提交仍将联系车头、房间密码、备注及旧区服/要求置空，避免草稿和历史车辆带入隐藏内容。

详情顶部展示游戏、状态和开局时间，已入座队友与空位通过座位图展示。点击已入座的头像可查看公开资料。发车详情隐藏历史记录里的区服、段位要求、语音、房间信息和备注。详情按角色提供加入、分享、管理和下车操作，从分享直接进入时可用左上角返回首页。

车头的分享与管理操作集中在同一排。开黑时间可在「管理队伍 → 编辑组队」里修改，散车也由「管理队伍」进入。

普通发车保留草稿和近期游戏设置；编辑、新建、再发一局相互区分。发布成功进入详情，可分享招人。加入成功后可在座位图查看队友的公开资料。小程序不自动进入游戏。

## 每日固定车

- 管理员在「我的 → 管理端 → 固定车」新增、编辑、暂停或启用计划，指定已有昵称且未封禁的车头、游戏、每天开始/结束时间、总人数与语音方式。表单按游戏、每日时段、人数与语音、车头四个区域展示；时间用滚轮选择，总人数用加减控件并注明含车头，保存前可看到时段/时长/人数预览。车头资料展示当前头像、昵称、群组、签名及已填写的Steam好友码、微信ID，未填写项明确提示。普通用户和组局员没有计划管理权限。
- 按北京时间每天零点后由现有每分钟定时任务生成当天新车，大厅访问也会补偿。保存或启用立即尝试生成当天的车；新建时当天开局时间已过则从次日开始。结束时间早于开始表示次日结束，起止时间不能相同。
- 每个计划每天至多一辆车，车辆和车头成员在同一事务生成；车头占1位，其余用户每天独立报名。封禁或未完善资料的车头不自动发车，异常在云函数日志记录，之后可重试；不补建已经结束的车辆。
- 修改计划只影响尚未生成的车辆。暂停不取消现有车，现有车按普通队伍编辑/上下车/散车；当天散车后不会自动复活，需要时手动另发。群组沿用生成时车头资料，不自动填入联系方式、密码或备注。固定车在大厅和详情显示「每日固定车」。
- 「我的」向所有用户展示「固定车」和「添加群组标识」两个入口，说明需求后可复制作者微信联系。固定车由作者通过管理端配置；群组由管理员在「管理端 → 群组」维护，用户在个人资料选择后，新发车带上群组标识。

## 车辆分享与提醒

- 列表转发和详情分享使用同一车辆标题、详情链接和5:4信息图：缺人/满员等状态、游戏、时间、当前/总人数及语音/区服等标签，不显示游戏平台标签，不带房间号和密码。
- 图片复用旧版车辆邀请卡样式；绘图失败使用品牌图，右上角菜单分享保留各页面自身内容。
- `from=share` 仅标记访问来源，不是权限凭据；朋友圈单页预览不发起业务请求或写本地欢迎状态。
- 微信分享事件必须由页面入口直接注册，维护要求见 [AGENTS.md](../AGENTS.md)；原生构建自动检查注册标记。
- 加入不依赖订阅授权；成员可自愿申请开打提醒。微信授权、云端发送和实际送达分别确认；QQ 不请求微信订阅模板。
- 现有 `startRemind` 定时器在开始前约10分钟提醒，按收件人记录结果并在窗口内重试临时失败；太晚上车可能错过扫描。散车尝试通知有额度的成员，发送失败不阻断散车。

## 个人资料与群组

- 管理员可在管理端新增、改名、停用和启用全部群组（最多200个，名称1–40字且不重复），普通用户及组局员无维护权限。配置从云端获取，日常维护无需发版；改名更新所有展示名称。停用不删除历史标识，已有用户可保留或移除，其他用户不可新选；大厅仍可按停用群组筛选。

- 浏览无需完善资料。新用户首次保存个人资料时须设置昵称和头像，发布或加入时会引导尚未设置昵称的用户完善资料。已有昵称的老用户可继续使用默认头像，签名和其他字段选填。
- 昵称、头像、签名、群组、常玩游戏、常玩时间、Steam好友码和微信ID为明确公开字段；排行榜与成员抽屉均展示已填写内容，未填写不显示。
- 群组最多10个、常玩游戏最多5个且每个最多40字、时间段最多5个。Steam好友码为最多20位数字字符串，保留前导零；微信ID最多32位字母、数字、下划线或短横线。
- 保存未传字段时保留旧值；空数组/空字符串表示主动清空。联系方式可点击图标或长按复制。
- 群组是标签，不限制跨群上车。发布/代开/接手时由服务端复制实际车头群组，客户端不能伪造；之后改资料不会追改旧队伍。筛选多个群组时任意匹配。
- 选项维护源为 `cloudfunctions/team/lib/profile-options.json`，维护步骤见 [维护与验收](维护与验收.md)。

## 官方推荐车

- 微信版下线投票入口、页面与分享，微信 `team` 云函数拒绝现行及旧版投票请求。历史票据保留，各平台前端按自身路由和后端接入运行。
- `startRemind` 每日北京时间 16:00 起从有效历史发车随机选取一局，沿用游戏、平台及容量，生成当天 21:00–23:00 的「官方推荐车」。无有效历史时跳过，23:00 后不补建。
- 官方车开始为 0 人、无车头、无成员。首位通过独立接手表单确认的人在事务中成为唯一车头；打开表单不占位，不能直接上车绕过接手。
- 接手固定推荐游戏、平台、时间和初始容量。联系方式、密码、备注提交为空；并发失败返回原车详情，同一车头重试不增加成员。
- `daily_play` 记录每日推荐结果，稳定车辆 ID 及事务避免重复建车；推荐过程不读取历史投票。

## 用户排行与管理

- 发车榜：累计已完成发车的队伍数，未接手系统空车不计。上车榜：累计加入其他车头的队伍数，同人同车只算一次，车头不重复算乘客。
- 各榜前10，前三名领奖台，列表从第4名起；仅展示真实用户。使用完整分页的队伍、成员、上车事件和资料，兼容 `_id` / `openid` / `_openid`；旧退出记录未留事件的无法追溯。
- 封禁/无昵称用户不登榜；返回公开资料及哈希标识，不公开原始身份和订阅偏好。
- 管理端包含概览、队伍、固定车、用户、举报、报错、反馈；可强制散车、封禁/解封、设置组局员和处理记录。入口隐藏不代替服务端权限验证。
- 举报/报错/反馈的提交人显示最新昵称，举报车头优先昵称，缺失时回退OpenID；用户管理卡片保留OpenID供配置核对。
- 反馈、报错、举报经过现有内容校验与限流；封禁用户可浏览，写操作被服务端拒绝。

发布与真机检查统一维护在 [维护与验收](维护与验收.md)，不再保留分散的已完成实施清单和过期测试数量。
