# 冷启动计划

> 日期：2026-09-19
> 现状：`推广文案.md` 的各渠道文案已发布过一轮，内容平台带来的实际使用者很少。
> 结论：**问题不在文案，在顺序。** 内容平台不是这个产品的冷启动渠道——冷启动的单位是「群」，不是「用户」。文案与配图不用重做，继续用。

---

## 1. 复盘：为什么发了没效果

三条结构性原因，与文案写得好不好无关：

1. **转化链路太长。** 站外内容到小程序要走五步以上：看到笔记 → 记住名字 → 打开微信 → 搜一搜 → 打开小程序 → 大厅里有车 → 留下。每一步都在流失，闲逛流量熬不到最后一步。
2. **需求时机错位。** 开黑是「现在就想打」的即时需求，而刷到笔记的人多半不在这个状态。内容平台给的是闲逛流量，不是需求流量。微信内的朋友圈比站外好一些，但同样受「大厅没车」限制。
3. **大厅供给太薄。** 新用户打开看到没有车，几秒内就会走，而且不会再来。第 9 节其实已经写了这条（「别在大厅空的时候大规模拉陌生人」），这次是先铺公开渠道、后做群，顺序反了，结果在预期之内。

内容平台不是没用，是**角色错了**：它该做「背书 + 承接搜索」——有人质疑「这什么小程序」时能搜到、有人搜品牌名时能找到——而不是「即时获客」。

## 2. 这个产品的增长结构

一次发车是一对多的传播：

```
车头发车 → 卡片丢进群 → 整个群看到（几十~几百人）→ 几个人点开 → 有人上车 → 这些人下次自己发车
```

推论：**打动一个群 > 打动一百个散客**。推广动作不是「发链接」，是「在群里真实使用」。

## 3. 行动计划

### 第 0 步 · 拉基线数据（今天，10 分钟）

「我的 → 管理端 → 概览」记下四个数：用户数、累计组队、上车人次、近 7 天发车趋势。

| 数据形态 | 判断 | 怎么做 |
| --- | --- | --- |
| 用户数很少（< 50） | 曝光问题 | 按下面第 1–4 步走 |
| 有用户，但几乎没人发车 | 产品问题 | 先别推广，去问 3 个用过的人为什么不用 |
| 发车正常，但上车少 | 分享 / 落地问题 | 查卡片标题、详情落地页、群里呈现 |

### 第 1 步 · 自己先当重度用户（本周起，每天）

这不是「dogfooding 走个流程」，而是这个产品的启动机制本身：你自己发车，大厅才不是空的；你每发一趟，整个群就被暴露一次。**你的日常发车行为就是推广，不需要额外的推广动作。**

具体做法是一次零成本的行为替换：你本来就要约人开黑，把「在群里喊一句今晚 9 点 CS2 还差两个」换成「发一张车卡片」。不多花一分钟，也不用开口求人。

- 每次开黑都用小程序发车，卡片丢进自己的群
- 两个目的：让大厅任何时候都有车；亲手试出「哪句话群友会点开」
- 不要用假车充数——群里的人点开发现是假的，比没有车更伤

**顺手记下别扭的地方**：自己天天用，会暴露一堆看数据看不出来的问题（发车要填的太多？时间选择不顺手？卡片上的信息不全？）。每遇到一个就记一条，攒几条一起改——这是最快的产品迭代，比任何用户调研都准。

### 第 2 步 · 渗透 3–5 个真实群（1–2 周）

**先纠正一个误解：起步不需要群，需要 1 个愿意点开卡片的队友。**

最小闭环是「你 + 1 个朋友」：发一趟车，把卡片发给一个朋友，他点开上车，产品就验证了。之后你们各自有自己的群，就变成两个群。群是这个过程的**结果**，不是前提。

**群从哪来**（按启动难度排序）：

| 来源 | 怎么做 |
| --- | --- |
| 你本来就在的群 | 微信 → 通讯录 → 群聊，从头划一遍，凡是「可能有人玩游戏」的都记下来：同学群、老乡群、同事群、兴趣群。信任度是现成的，一个新群都不用加 |
| 游戏里认识的人 | 打完一局配合好的就加好友、约下次。人攒到 5–8 个建个固定搭子群——自建的群最可控，也最活跃 |
| 游戏内公会 / 战队 | CS2 战队、王者荣耀战队、游戏内公会大多自带群，加入一个活跃的，它的群就是目标群 |
| KOOK / Discord 频道 | 产品支持 KOOK 语音，说明目标用户就在这些频道里，频道里天天有人找队友 |
| 学校 / 公司 | 学生找宿舍楼群、社团群、班级群；上班族找公司游戏群。这两处玩家密度最高 |

**不要做的事**：加陌生群、发推广链接。群主会踢你，群友会举报，而且陌生群对你是零信任——产品要的是「群里有活人愿意点开卡片」，陌生群给不了。

**在群里怎么做**：

- **不要**说「我做了个工具大家来用」——最容易被无视的开场
- 就正常发车：玩什么、几点、几缺几，卡片丢进去
- 只有被问「这是什么」时才简单说两句

每个群的目标：

- ≥ 3 人点开过卡片
- ≥ 1 人**自己**发过车（这条最关键，说明他不是在给你面子）

**如果一个群都没有**：先别推广，去当一个真实玩家。混一两个游戏社区（NGA 版块、贴吧、B站评论区、游戏内公会），真心参与一两周，认识人之后再谈用产品。跳过这一步直接推广，效果一定是零。

### 第 3 步 · 先跑通一个群，再复制

目标不是 100 个用户，是**1 个每次开黑都顺手用它发车的群**。同一时间只攻 1–2 个群，别铺开。

### 第 4 步 · 搜一搜（免费被动流量）

**当前状态（2026-09-19）：搜不到，收录为 0。** 已确认不是漏配——小程序名里有「游戏搭子」关键词，4 个游戏落地页与 `sitemap.json` 收录规则都已就位。判断：这不是配置问题，而是搜一搜对新小程序本来就不给排名（排名受用户行为数据影响很大，没用户就没排名）。**这条线押后一个月再看，期间不再投入精力。**

排查过的项，留档备查：

- 小程序须为**已发布正式版**：开发版 / 体验版不会被搜一搜收录
- `sitemap.json` 随代码包发布，改了要重新上传才生效
- 页面数据靠云函数异步加载，爬虫渲染时可能只拿到空列表，没有可索引内容
- 加更多游戏落地页**解决不了收录为 0**：收录是「门」的问题，不是「房间数量」的问题

等有了基础用户量再回来做两件事：确认收录是否恢复；给 CS2 / 永劫无间 / 英雄联盟 / DOTA2 补落地页，按搜一搜实际搜索量排优先级。

搜一搜的价值不变：**只在需求发生时触发**（真的在找队友的人才会去搜），比闲逛流量精准得多——只是它跑在后面几棒，不是第一棒。

### 第 5 步 · 内容平台改成「承接」

- 继续发，一周 1–2 篇，长期挂着，但不再指望它直接带人
- 它的作用变成两条：被人质疑时能搜到、证明东西是真的；有人搜品牌名时能找到
- `docs/promo/` 的物料和上面的文案照用，不用重做

## 4. 组局员：现成的群主杠杆

代码里已有「组局员」角色（`organizers` 集合或 `ORGANIZER_OPENIDS` 环境变量，管理员在「我的 → 管理端 → 用户」授予）：组局员能**帮群友代开车**，即替别人当车头发车。

冷启动用法：群里总有人「懒得弄，你帮我发一下」——找到群里的活跃分子或群主，给他们开组局员，让他们能代群里的人发车。这比说服每个群友自己发车轻得多。

## 5. 每周复盘

每周日固定看三个数：新增用户、发车数、上车人次。

- 健康信号是**某个群集中出量**（一个新用户带来同群的好几个），不是均摊式的缓慢增长
- 若四周、5 个群试下来仍只有你自己在发车，问题不在推广在需求——回去访谈那些点开过卡片的人

## 6. 可选的产品侧改进

按预期收益排序，值得做时再做：

| 改进 | 现状 | 说明 |
| --- | --- | --- |
| 上车后的分享引导 | 上车只弹一个「已上车」提示 | 目前每趟车只靠车头传播；上车后加一步「拉朋友一起」，把乘客也变成传播节点 |
| 搜一搜关键词扩展 | 4 个游戏有落地页，目录里还有 4 个没有 | 给 CS2 / 永劫无间 / 英雄联盟 / DOTA2 补落地页，按实际搜索量排优先级 |

## 7. 预期

- 前 2–3 周数据平是正常的，群渗透本来就是慢变量
- 这条路走通的标志：**出现「不是你发的车」**
- 至少跑满一个月、5 个群，再谈要不要换方向
