# 来开黑

微信小程序：给游戏好友发车组队（Steam / 手游 / 端游 / 主机），把卡片丢进群就能上车。

## 本地开发

1. 用微信开发者工具打开本目录，环境选 `cloud1`（`cloud1-d9gniyjzh4e2ffb1c`）
2. 右键 `cloudfunctions/team` → 上传并部署：云端安装依赖
3. 编译后从「发车」发一条，再从「大厅」或分享卡片上车

云函数第一次成功调用后，会自动创建 `users`、`teams`、`members`、`feedback` 四个集合。

| 字段 | 填什么 |

| 备注 `thing11` | 即将开打，请准时上线 / 有人上车了 / 人已经齐了 / 你被请下车了 / 这趟已经散了 |

开打前 5 分钟，定时器会给车上所有人推「即将开打」。发车、点「开打前微信提醒我」时会请求授权。「有人上车 / 人齐了」只发给车头。

改模板后同步改 `constants.js` 和云函数 `sendSubscribe`，并重新上传 `team`（须带触发器）。

## 意见反馈

要真正发到邮箱：

1. 打开 [foxmail.com](https://mail.qq.com) 或 QQ 邮箱网页版 → 设置 → 账户 → 开启 **POP3/SMTP** → 生成**授权码**（不是登录密码）
2. 把授权码填进 `cloudfunctions/team/mail.local.js` 的 `SMTP_PASS`
3. 右键 `cloudfunctions/team` → **上传并部署：云端安装依赖**（必须勾选安装依赖，否则发不出）

`mail.local.js` 含密码，不要提交。发信失败时，页面会弹出具体原因；未发出的反馈仍在云开发控制台 `feedback` 集合里。

## 回归检查

运行 `node --test tests/team-regressions.test.js`，检查身份判定、通知失败补发和上车授权。

开打提醒按收件人记录已处理结果（发送成功或按偏好跳过），在原提醒窗口内每 1 分钟补发失败者；全部处理完才标记整趟已提醒。关闭提醒的人不发送、也不阻塞结账。窗口结束后不再补发。发送成功但记录写入失败、定时任务重叠时仍可能重复发送，需在云端观察日志。

车头身份只依据队伍 OpenID 或明确标为车头的成员 OpenID。历史记录若两处都缺少身份标识，需要人工核对修复，不再通过昵称自动认领。

修改后重新上传并部署 `cloudfunctions/team`（包含定时触发器），并在微信开发者工具中编译、用真机验证订阅消息。

## 页面与授权交互

订阅授权由 `wx.requestSubscribeMessage` 调起微信原生界面。仅在发车、上车、主动点击提醒入口时请求，浏览队伍不再弹授权。详情用页内文字展示授权结果；头像昵称抽屉是资料填写，不是通知授权。

开打前 5 分钟进入提醒窗口，每分钟扫描一次，正常约提前 4–5 分钟触发，实际送达受云函数执行和微信服务影响。原有定时触发器须同步更新为每分钟执行。

列表只向视图传递当前筛选结果，卡片复用已格式化的数据；相同并发读取合并，完成后清除，不缓存人数和状态。大厅、我的、详情支持下拉刷新。

## 个人提醒偏好

「我的」提供原生 `switch` 开关，云端 `users.notifyEnabled` 保存偏好。未设置时沿用已有的提醒流程（不等于已获微信授权）。关闭后，发车/上车不再申请订阅，云端也停止发送组队消息；修改昵称头像保留该偏好。

开启开关直接调用 `wx.requestSubscribeMessage`；仅当微信返回 accept 后保存开启。发车/上车时仍需调用该原生 API 获取本次订阅，无需另点详情提醒。设置页通过 `wx.getSetting({ withSubscriptions: true })` 读取微信状态，通过 `wx.openSetting({ withSubscriptions: true })` 打开原生设置。没有返回模板状态时不推断为拒绝或已授权。

一次性订阅的记住选择不等于永久授权，也不表示剩余可发送次数。当前多个事件共用一个模板，其他通知可能消耗该模板的订阅次数，开打提醒仍取决于有效授权。长期订阅资格及模板类型需在微信后台确认，不能由前端开关转换。

新增保存接口和发送前偏好检查需要重新部署 `team` 云函数。

## 界面风格

采用浅灰底、白色卡片和紫蓝主色的「清爽开黑风」，配套同色原生 tabBar 图标。大厅卡片突出游戏、时间和人数，房间号在详情查看；详情展示成员头像与空位，底部集中加入/分享操作，车头管理采用底部菜单，散局项单独标红（原生 ActionSheet 不支持逐项设色），最终散局确认仍使用微信原生弹窗。

发车页默认折叠选填信息，编辑和再发时展开，折叠不清空内容。「我的」通过发起/加入、进行中/历史切换队伍，提醒设置按需展开，页脚显示版本号和意见反馈。

## 品牌图片

头像与配套插画使用内置 imagegen 生成，原图及提示词位于 `docs/brand/`。公众平台头像可使用 `docs/brand/来开黑头像.jpg` 手动上传。大厅与空状态插画、发车页品牌头像采用 `miniprogram/images/brand/` 下压缩版本，总计约 50 KB；图片有固定尺寸，空状态按需展示并懒加载。

## 公开游戏资料

「我的」点击头像或编辑资料，可以选填 Steam 好友代码、游戏内 ID、KOOK ID 和个人简介。房间访客点击成员头像可查看最新公开资料，点击账号行通过微信原生剪贴板 API 复制。清空字段并保存后，后续查询不再显示；未填写的账号行隐藏。

`getPublicProfile` 按房间 ID 和成员记录 ID 查询，校验成员属于该房间，仅返回昵称、头像及上述四个公开字段。旧客户端仅更新昵称头像时保留公开字段，编辑资料也保留提醒偏好。无需新增集合，但需重新上传并部署 `cloudfunctions/team`，否则旧云函数无法识别新查询操作。
