# 开黑星球｜游戏搭子

微信小程序：给游戏好友发车组队（Steam / 手游 / 端游 / 主机），把卡片丢进群就能上车。

## 本地开发

1. 用微信开发者工具打开本目录，环境选 `cloud1`（`cloud1-d9gniyjzh4e2ffb1c`）
2. 右键 `cloudfunctions/team` → 上传并部署：云端安装依赖
3. 编译后从「发车」发一条，再从「大厅」或分享卡片上车

云函数第一次成功调用后，会自动创建 `users`、`teams`、`members`、`feedback`、`reports`、`rate_limits`、`admins`、`organizers` 八个集合。其中 `reports` 同时存举报和用户报错，用 `kind` 区分；`rate_limits` 记录防刷时间窗；`admins` 存放管理员 OpenID；`organizers` 存放组局员 OpenID。

## 订阅消息

已接入模板「游戏组局即将发车」（`6CGZ2ttjMY5Dl_PC2TrrXmrF-KT8awGU7SLPHif2EJ4`）：

| 字段 | 填什么 |
| --- | --- |
| 日程标题 `thing5` | 游戏名 |
| 开始时间 `time6` | 开打时间 |
| 备注 `thing11` | 即将开打，请准时上线 / 这趟已经散了 |

一次性订阅每局只保证一条：默认留给开打提醒，因此**每局最多收到一条通知**。开打前 10 分钟，定时器给车上所有人推「即将开打」；若车头提前散了这趟，已订阅的成员改为收到「这趟散了」，不再有开打提醒。发车、上车、点「开打前 10 分钟提醒我」时会请求授权。不再发送「有人上车 / 人齐了」（会抢占仅有的额度，导致开打提醒收不到）。开打前 10 分钟内才上车的人错过本轮扫描，不再补发。

改模板后同步改 `constants.js` 和云函数 `sendSubscribe`，并重新上传 `team`（须带触发器）。

## 意见反馈

「我的」可按模板提交反馈，云函数写入 `feedback` 集合，并发送到 `liuyi4781@foxmail.com`。

要真正发到邮箱：

1. 打开 [foxmail.com](https://mail.qq.com) 或 QQ 邮箱网页版 → 设置 → 账户 → 开启 **POP3/SMTP** → 生成**授权码**（不是登录密码）
2. 把授权码填进 `cloudfunctions/team/mail.local.js` 的 `SMTP_PASS`
3. 右键 `cloudfunctions/team` → **上传并部署：云端安装依赖**（必须勾选安装依赖，否则发不出）

`mail.local.js` 含密码，不要提交。发信失败时，页面会弹出具体原因；未发出的反馈仍在云开发控制台 `feedback` 集合里。

## 管理端

「我的」页脚在管理员账号下会多出一个「管理端」入口（`pages/admin/admin`）。管理端分六个标签：

| 标签 | 内容 |
| --- | --- |
| 概览 | 累计组队、进行中、缺人/满员、用户数、上车人次、待处理举报/报错/反馈；最活跃游戏排行、平台分布、近 7 天发车趋势 |
| 组队 | 当前进行中的队伍，可强制关闭 |
| 用户 | 全部用户，可搜昵称或 OpenID、只看已封禁、封禁 / 解封、授予 / 取消组局员 |
| 举报 | 用户对某趟车的举报，车头按昵称显示，可按未处理筛选、标记已处理 |
| 报错 | 用户上报的页面错误，含报错信息与设备信息，可标记已处理 |
| 反馈 | 与「意见反馈」同源的记录，可标记已处理 |

「强制关闭」走 `adminCancelTeam`，不受车头身份限制，关闭后写入 `cancelledBy: "admin"` 并通知车上所有人（含车头）。车头自己的「散了这趟」仍然只允许车头操作。

举报、报错、反馈列表里的人一律用昵称指认：提交人显示 `users` 集合里的最新昵称，被举报车的车头由记录的 OpenID 换算成昵称（查不到时才回退显示 OpenID）。「用户」标签的卡片上保留 OpenID 小字，供配置 `ADMIN_OPENIDS`、`admins` 时复制。

### 封禁 / 解封

封禁写入 `users` 记录的 `banned`、`banReason`、`bannedAt`。被封禁的账号**只能浏览**：发车、上车、改资料、反馈、报错、举报全部被云函数拒绝（返回 `code: "BANNED"`），大厅和详情仍可正常查看。封禁时不能选管理员，也不能封自己。

「用户」标签支持按昵称或 OpenID 搜索，并可切换只看已封禁；每条显示发车数、上车数、封禁原因。封禁时弹窗可填原因。

最活跃游戏按 `进行中场次 × 3 + 总场次 + 上车人次 ÷ 2` 打分排序，因此既能反映「当下有人玩」，也兼顾历史总量。

管理员身份有两种配置方式，满足其一即可：

1. 云函数环境变量 `ADMIN_OPENIDS`，多个 OpenID 用英文逗号分隔
2. `admins` 集合里以管理员 OpenID 为 `_id` 建立一条记录

前端只在 `getProfile` 返回 `isAdmin: true` 时才显示入口；所有 `admin*` 接口在云函数侧同样会校验身份，没有权限时返回「没有管理权限」，不依赖前端隐藏。

### 组局员

组局员是「能帮群友发车」的角色，进不了管理端。管理员在管理端「用户」页授予 / 取消（`adminSetOrganizer`），写入 `organizers` 集合；也可以用云函数环境变量 `ORGANIZER_OPENIDS`（逗号分隔）配置，但环境变量里的名单不能在管理端改动。被封禁或还没设置昵称的用户不能被设为组局员。

组局员和管理员在发车页切到「帮群友发车」，按昵称搜索目标用户（必须带关键字，只回昵称与头像，最多 20 条），选中后以对方身份发车：队伍的车头是那个人，他能在「我的」里看到并管理这趟车。目标用户已封禁或还没填头像昵称时代开会被拒绝。代开会记下代开人昵称，身份标识一律不下发。

## 防刷限流

写接口按「动作 + 用户」在时间窗内计数，超限直接拒绝。记录写在 `rate_limits` 集合，`_id` 为 `动作_OpenID`：

| 动作 | 窗口 | 上限 |
| --- | --- | --- |
| 发车 `createTeam` | 30 分钟 | 8 次 |
| 上车 `joinTeam` | 60 秒 | 6 次 |
| 反馈 `submitFeedback` | 30 分钟 | 5 次 |
| 举报 `submitReport` | 10 分钟 | 5 次 |
| 报错 `submitBug` | 5 分钟 | 3 次 |

限流记录读写失败时不阻断主流程（仅记日志）。举报另有 24 小时同一目标去重，重复举报直接返回「你已经举报过这趟了」。

## 举报与报错

- **举报**入口在队伍详情页（非车头可见），理由为广告营销 / 色情低俗 / 辱骂骚扰 / 虚假信息 / 违法违规 / 其他，可补充说明。云函数校验目标队伍存在、理由合法，并记录车头 OpenID 便于追溯。
- **报错**入口在「我的」页脚。页面按模板填写「我做了什么 / 出现了什么」，可附错误信息；`app.js` 的 `onError` 会捕获未处理异常并预填。两者都过 `msgSecCheck` 与本地违禁词。

举报与报错都写入 `reports` 集合（`kind` 为 `report` / `bug`），不额外发邮件，统一在管理端处理。

## 回归检查

运行 `node --test tests/*.test.js`，覆盖身份判定、通知失败补发、上车授权、防刷限流、举报/报错、管理端统计，以及游戏落地页与收录规则、发车表单校验、时间线预览。

开打提醒按收件人记录已处理结果（发送成功或按偏好跳过），在原提醒窗口内每 1 分钟补发失败者；全部处理完才标记整趟已提醒。关闭提醒的人不发送、也不阻塞结账。窗口结束后不再补发。发送成功但记录写入失败、定时任务重叠时仍可能重复发送，需在云端观察日志。无订阅额度（43101）等微信终态错误直接视为已处理，不再每分钟重试；提醒扫描对多趟队伍有限并发，`config.json` 已设置 20 秒超时。

头像上传到云存储，库里只存 `fileID`。免费开发环境的存储权限锁定为「仅创建者可读写」，客户端之间直接读图会 403，因此读接口（`getTeam` / `getPublicProfile` / `getProfile`）均由云函数用 `getTempFileURL` 把 fileID 换成有时效的 HTTPS 链接再返回——服务端不受存储权限限制，`<image>` 也无需配置下载域名。老数据里的 base64 仍可用于展示，但一旦重新上传头像就会写入 fileID 并清掉 base64。`getTeam` 只对车头下发成员标识，普通访客拿不到任何 OpenID。

新上传的头像会先由云函数 `downloadFile` 取回、调用 `security.imgSecCheck` 检测；命中违规（87014）时删除该文件并拒绝保存。前端上传前用 `compressImage` 压到 400px 宽，满足检测接口的尺寸/体积限制。文本类内容（游戏名、进房方式、密码、区服、水平、备注、昵称、签名、意见反馈）在入库前由云函数调用 `security.msgSecCheck` v2 检测，仅 `suggest=risky` 拦截，`review` 不误伤。检测接口自身异常时不阻断提交（仅记日志），由平台巡检兜底。`config.json` 的 `permissions.openapi` 需保留 `security.imgSecCheck` 与 `security.msgSecCheck`，否则云函数调用会失败。

车头身份只依据队伍 OpenID 或明确标为车头的成员 OpenID。历史记录若两处都缺少身份标识，需要人工核对修复，不再通过昵称自动认领。

大厅分页查询 `where endAt > now` + `orderBy createdAt desc` 建议在云数据库为 `teams` 建 `endAt`、`createdAt` 复合索引；缺索引时查询会报错，`listTeams` 自动退化为内存排序扫描（上限 200 趟），功能不中断但数据量大时会漏掉较老的队伍。已取消 / 已过期的车在云函数内存里跳过，不占分页名额。

修改后重新上传并部署 `cloudfunctions/team`（包含定时触发器），并在微信开发者工具中编译、用真机验证订阅消息。

## 页面与授权交互

订阅授权由 `wx.requestSubscribeMessage` 调起微信原生界面。仅在发车、上车、主动点击提醒入口时请求，浏览队伍不再弹授权。详情用页内文字展示授权结果；头像昵称抽屉是资料填写，不是通知授权。

开打前 10 分钟进入提醒窗口，每分钟扫描一次，正常约提前 9–10 分钟触发，实际送达受云函数执行和微信服务影响。原有定时触发器须同步更新为每分钟执行。

列表只向视图传递当前筛选结果，卡片复用已格式化的数据；相同并发读取合并，完成后清除，不缓存人数和状态。大厅、我的、详情支持下拉刷新。

大厅默认按创建时间倒序（最新发布在最上面），可切换「最热」（已上车人数）。支持按关键词搜索，匹配游戏名 / 区服 / 段位 / 备注，忽略大小写与首尾空白。列表滚动到底自动加载下一页，云函数 `listTeams` 按 `createdAt` 倒序游标分页，每页 20 条（客户端可指定，上限 50），返回 `hasMore` 与 `nextOffset`；筛选、搜索、切换排序只在已加载到本地的数据上重排，不重新请求。加载完显示「没有更多了」；搜索只在已加载的车里匹配，没搜到但还有下一页时给「继续加载更多」入口。

## 提醒授权

不做应用内提醒开关：真正的开关是微信侧的订阅授权，应用内再放一个只会让人困惑。发车、上车时直接调用 `wx.requestSubscribeMessage` 申请本次订阅；没有拿到授权时，详情页的「开打前 10 分钟提醒我」可再点一次补授权。想彻底关闭，用微信小程序右上角 → 设置 → 订阅消息。

一次性订阅的记住选择不等于永久授权，也不表示剩余可发送次数。当前每局只保证一条通知（见「订阅消息」），其他通知不再共用该模板额度。长期订阅资格及模板类型需在微信后台确认，不能由前端转换。

## 分享与搜索收录

聊天分享落地到 `pages/team/detail?id=队伍ID`；大厅、发车、详情、我的、游戏页都支持分享到朋友圈。朋友圈打开的是**单页模式**：微信把页面渲染成一张静态卡片，没有 tabBar 也不能跳转，只保留「前往小程序」入口。`utils/runtime.js` 的 `isSinglePage()` 负责识别（优先取运行模式，旧基础库回退到场景值 1154），单页模式下各页面用 `timeline-preview` 组件替代正文，并隐藏欢迎信。

`pages/game/game` 是给搜一搜收录的游戏落地页，路径形如 `pages/game/game?game=wangzhe`。`game` 参数可以传 slug、seoKey 或游戏名，另兼容 `g` / `id` / `slug` / `name`（`resolveGameQuery` 统一归一化）。`sitemap.json` 只允许首页和带 `game` 参数的这一个页面被收录，其他页面与其它参数一律 disallow。

`utils/games.js` 的 `GAME_SEO` 给 4 个游戏配了独立的标题与描述（王者荣耀 / 三角洲行动 / 无畏契约 / 和平精英），`GAME_CATALOG` 里另有 CS2 / 永劫无间 / 英雄联盟 / DOTA2。分享与收录传 `seoKey`：多数游戏与 slug 相同，和平精英的 slug 是 `pubg`、seoKey 是 `peace`。想让更多游戏的落地页被搜到，往 `GAME_SEO` 补条目即可。

## 界面风格

采用浅灰底、白色卡片和紫蓝主色的「清爽开黑风」，配套同色原生 tabBar 图标。大厅卡片突出游戏、时间和人数，房间号在详情查看；详情展示成员头像与空位，底部集中加入/分享操作，车头管理采用底部菜单，散局项单独标红（原生 ActionSheet 不支持逐项设色），最终散局确认仍使用微信原生弹窗。

发车页默认折叠选填信息，编辑和再发时展开，折叠不清空内容。开始时间配了「现在 / 今晚 / 自定义」快捷选项，时长可选 1 / 2 / 3 小时或自定义（30 分钟–24 小时，步进 30 分钟）。「我的」把「发起 / 加入」和「进行中 / 历史」合并到同一行（数量并进 tab），资料卡显示签名，底部是极简页脚（反馈、报错、协议、版本号）；组局员额外显示「帮群友发车」，管理员额外显示管理端入口。队伍详情底部对非车头提供「举报这趟车」入口。首次进入会展示一封欢迎信（友好相处 / 社区公约），确认后不再出现，「我的」可再次打开公约。

## 版本号

版本号按运行环境取值：**正式版**显示微信后台上传的版本号，**开发版/体验版**显示代码里 `miniprogram/utils/constants.js` 的 `APP_VERSION`。两者本来就允许不同——正式版反映线上实际发布的包，开发版反映本地代码，不必强求一致。

显示格式上，开发版/体验版带环境标注（如 `v1.6.1 · 开发版`），正式版只显示版本号本身（如 `v1.6.1`）。

发版时：上传代码时把微信后台的版本号填成和本地 `APP_VERSION` 相同的版本，正式版就会显示同一个数字；忘填的话，正式版会一直显示上一次上传的版本号。

## 品牌图片

头像与配套插画位于 `docs/brand/`。公众平台头像用 `docs/brand/开黑星球头像.jpg`。大厅与空状态插画、发车页品牌头像采用 `miniprogram/images/brand/` 下压缩版本；头像运行时约 12 KB，图片有固定尺寸，空状态按需展示并懒加载。

## 签名

「我的」点击头像或编辑资料，可以改头像、昵称和一个不超过 50 字的签名。签名是自由文本，建议用户把 Steam 好友码、常玩时间等写进去，不再单列 Steam / 游戏 ID / KOOK 字段。房间访客点击成员头像可查看对方的头像、昵称和签名。清空签名并保存后，后续查询不再展示。

`getPublicProfile` 按房间 ID 和成员记录 ID 查询，校验成员属于该房间，仅返回昵称、头像和签名。旧客户端仅更新昵称头像时保留已有签名。无需新增集合，但需重新上传并部署 `cloudfunctions/team`，否则旧云函数无法识别新查询操作。
