# P0 隔离验证工程

这里用于验证 uni-app + Vue 3 + TypeScript + Wot UI 的组件和编译链，不是正式迁移工程。为减少 P0 的变量，直接采用 DCloud 官方 vite-ts 模板的基础依赖组合，不引入完整 unibest 模板；P1 再根据结果配置工程能力。

## 使用

```sh
cd experiments/p0-uniapp
npm ci
npm run check:matrix
npm run dev:h5
```

执行目录为仓库根目录下的 experiments/p0-uniapp。使用 Node 24.22.0 / npm 11.19.1 做首次验证。依赖与 lockfile 固定后重现结果，不对根工程安装依赖。

- `check:matrix` 顺序执行类型检查与 H5、微信、独立 QQ、支付宝、抖音编译；任一失败最终返回非零，继续输出其他端的结果。
- 日志和机器可读结果保存在 `dist/p0/`，构建产物及 node_modules 不提交。
- `dist/build/mp-*` 可供各自开发工具导入；AppID 留空，需使用所属测试应用配置才能做真实登录和真机验证。不要将该实验上传到生产 AppID。
- mp-qq 只验证独立 QQ 目标的编译能力，不证明“QQ 内运行微信小程序”路线可用。

## 已包含的原型能力

1. Wot 按钮、输入框、底部弹窗及原生日期选择器。
2. 空加入方式的本地错误、正确输入反馈、图片本地选择（不上传）。
3. 宿主公开信息与 API 能力检查。
4. 小程序宿主登录 code 获取诊断，不输出 code，不保存 code，不提交至任何服务；H5 明确不执行该操作。

本工程不初始化 wx.cloud，不连接生产环境，不读取或写入真实大厅/成员数据，不包含模拟上车接口。获取到 code 也不等于完成服务端身份认证。

独立 HTTP 探测源代码在 `cloudfunctions/p0Health/`。部署并确认公网路由后，将 `.env.example` 复制为 `.env.local`，设置 `VITE_P0_HEALTH_URL` 为对应 HTTPS `/p0/health` 地址，再运行/构建；未配置时探测按钮禁用。探测只检查固定状态响应，不发送凭据或调用 team。

2026-10-15：路由和 H5 实际调用已通过，本机已在 git 忽略的 .env.local 中配置探测 URL。后续拉取代码时仍需自行填写 .env.local；没有把本地环境配置提交为公共默认配置。

可执行 `npm run check:http -- https://测试域名/p0/health` 重新验证公开传输接口，输出到 dist/p0/http-results.json。此脚本不验证平台用户、数据库和组队业务。
